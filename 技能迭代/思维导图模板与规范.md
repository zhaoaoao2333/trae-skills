# 思维导图模板与规范

## 一、总则

### 核心定位
思维导图是页面架构与功能模块的**可视化蓝图**，用于：
1. 梳理产品完整页面/功能结构
2. 作为PRD和原型的输入源
3. 团队沟通与评审的参考

### 适用范围
- 移动端App（页面结构主导）
- 管理后台（功能模块主导）
- 通用思维导图（不限端）

### 输出格式
- **主文件**：FreeMind (.mm) — XML格式，可导入XMind/FreeMind/Freeplane/MindManager
- **备份文件**：Markdown (.md) — 无序列表格式，便于阅读和版本管理

## 二、移动端模板（页面结构主导）

### 2.1 结构原则

```
根节点
├── App端
│   ├── 注册登录流程（前置页面）
│   ├── Tab1首页（一级页面）
│   │   ├── 板块A（页面内的视觉区域）
│   │   │   ├── 内容描述
│   │   │   ├── 交互描述
│   │   │   └── → 跳转至：目标页面
│   │   ├── 板块B
│   │   └── 底部TabBar
│   ├── Tab2首页
│   ├── ...
│   ├── 游戏内通用页面（如有）
│   └── 专项流程页面（如有）
```

### 2.2 节点层级规则

| 层级 | 内容 | 示例 |
|------|------|------|
| 第1级 | 端名称 | App端 |
| 第2级 | 页面名称/Tab名称 | 游戏Tab首页 |
| 第3级 | 页面内板块/区域 | 顶部个人资产栏 |
| 第4级 | 板块内容/交互/跳转 | Gold余额显示 |
| 第5级+ | 子页面展开（仅唯一入口时） | 匹配等待页详细内容 |

### 2.3 板块节点写法

**板块有交互/可跳转** → 继续往下展开：
```
游戏列表（金刚区，4列网格卡片）
  - Ludo卡片：封面 + 在线人数 + 快速开始按钮
    - 操作：点击卡片 → 跳转至：匹配等待页
  - Jackaroo卡片（结构同Ludo）
  - 分类Tag筛选（全部/棋牌/休闲/热门）
  - 搜索框（搜索游戏名称）
```

**板块无交互** → 描述内容和逻辑即可：
```
等级XP进度条
  - 显示当前等级和升级进度
  - XP来源：游戏竞技/社交互动/任务/消费行为
  - 每日XP上限可配置
```

### 2.4 唯一入口与跳转引用规则

**核心原则：页面信息只在一处详细定义，其他地方通过精确跳转引用。**

#### 判断标准

| 情况 | 处理方式 |
|------|---------|
| 当前页面是某目标页面的**唯一入口** | 目标页面就地展开（继续往下画子节点） |
| 当前页面**不是唯一入口**（多处可进入） | 只写 `→ 跳转至：XXX页`，不展开 |

#### 跳转引用格式
统一使用：`→ 跳转至：XXX页`

#### 常见"非唯一入口"页面
- 个人主页（头像、好友列表、更多Tab等多处可进）
- 消息中心（顶部消息入口、更多Tab等多处）
- 商城（Diamond入口、更多Tab等）
- 充值中心（Gold入口、VIP页等）
- 设置页（更多Tab等）

这些页面选择一个**主入口**首次展开（通常在"更多Tab"首页），其他位置只写引用。

### 2.5 交互效果描述规范

**不用强制标签**（如【内容】【作用】），用自然文字描述。

交互效果描述要点：
- 描述用户操作的直接反馈（如"点击后弹出XX"）
- 描述动画/视觉效果（如"卡片翻转""脉冲动画"）
- 描述状态变化（如"按钮变为不可点击""图标高亮"）

示例：
```
Quick Play按钮
  - 快速匹配最近玩过的游戏
  - 点击后进入匹配等待页
  - 匹配动画：雷达搜索脉冲效果
  - 匹配成功：对手信息弹窗 + VS动画 + 屏幕闪白
```

### 2.6 页面状态覆盖

核心页面需覆盖以下状态（在节点中自然描述，不强制标签）：
- 常规态：正常数据展示
- 空状态：无数据时的引导（插图+文案+操作按钮）
- 加载态：骨架屏或加载动画
- 错误态：网络异常/请求失败的提示与重试

## 三、管理端模板（功能模块主导）

### 3.1 结构原则

```
根节点
├── 管理端
│   ├── 模块1（一级功能模块）
│   │   ├── 子功能1
│   │   │   ├── 数据字段
│   │   │   ├── 操作说明
│   │   │   └── 业务规则
│   │   ├── 子功能2
│   │   └── ...
│   ├── 模块2
│   └── ...
```

### 3.2 节点层级规则

| 层级 | 内容 | 示例 |
|------|------|------|
| 第1级 | 端名称 | 管理端 |
| 第2级 | 功能模块名称 | 赛事管理 |
| 第3级 | 子功能 | 锦标赛创建/编辑/删除 |
| 第4级 | 数据字段/操作/规则 | 查询条件/操作按钮/校验规则 |
| 第5级+ | 字段明细 | 用户ID/用户名/手机号 |

### 3.3 模块节点写法

每个模块按以下维度自然展开（不用标签，直接描述）：

```
赛事管理
  - 平台赛事全生命周期管理
  - 锦标赛创建/编辑/删除
    - 创建表单：名称/时间/类型/赛制/奖励/报名条件
    - 每游戏独立管理
    - 名称唯一性校验
    - 时间冲突检测
  - 状态管理
    - 状态流转：草稿 → 报名中 → 进行中 → 已结束
    - 草稿→报名中需所有参数完整
    - 进行中→已结束需所有比赛完成
  - 参与者管理
    - 参与者列表：用户信息/报名时间/状态/排名
    - 搜索/筛选/导出
  - 结果管理
    - 结果录入/修改/确认
    - 奖励发放
```

### 3.4 管理端特殊规范

- 参考海外后台风格（左侧导航菜单 + 主内容区）
- 数据字段写明字段名（便于开发对接）
- 业务规则和校验逻辑明确写出
- 权限相关标注可见角色
- 审计操作标注日志记录要求

## 四、通用规范

### 4.1 节点文字
- 每个节点文字控制在25字以内
- 超长描述拆分为多个子节点
- 不使用模糊表述（如" etc." "..." "相关功能"）

### 4.2 标注规范

| 标注 | 含义 | 使用场景 |
|------|------|---------|
| [待确认] | 需要PM确认的内容 | 不确定的功能/规则 |
| [AI补充] | AI基于常识补充的节点 | 行业通用模块补充 |
| [MVP] | 首次交付的最小可用范围 | 核心路径功能 |
| [Phase 2] | 后续阶段实现 | 预留功能 |

### 4.3 AI补充限制
- AI补充节点不超过总节点数的20%
- 补充的必须是行业通用模块（如设置、帮助、关于等）
- 不可编造竞品功能或不存在的业务逻辑

### 4.4 层级控制
- 移动端：不限层级，以完整描述为目标
- 管理端：不限层级，以字段级明细为目标
- 同层级节点必须属于同一逻辑范畴，无包含关系

### 4.5 mm文件格式要求

```xml
<?xml version="1.0" encoding="UTF-8"?>
<map version="1.0.1">
  <node TEXT="项目名称 — 思维导图">
    <node TEXT="App端">
      <node TEXT="页面名称">
        <node TEXT="板块名称">
          <node TEXT="内容/交互描述" />
        </node>
      </node>
    </node>
    <node TEXT="管理端">
      ...
    </node>
  </node>
</map>
```

- XML格式正确，可被思维导图工具正常导入
- 使用 `TEXT` 属性存储节点文字
- 不使用 richcontent（保持简洁）

## 五、质量检查清单

| # | 检查项 | 检查标准 |
|---|--------|---------|
| 1 | 结构完整性 | 一级分支覆盖核心主题全部范围 |
| 2 | 唯一入口规则 | 页面信息只定义一次，非唯一入口只写引用 |
| 3 | 跳转格式统一 | 所有引用使用 `→ 跳转至：XXX页` |
| 4 | 节点文字 | 25字以内，无模糊表述 |
| 5 | 逻辑并列 | 同层级节点属同一逻辑范畴 |
| 6 | 标注规范 | [待确认]/[AI补充]/[MVP] 使用正确 |
| 7 | AI补充占比 | 不超过20% |
| 8 | mm文件可导入 | XML格式正确 |
| 9 | 交互描述 | 核心页面有交互效果描述 |
| 10 | 状态覆盖 | 核心页面覆盖常规/空/加载/错误态 |

## 六、使用流程

1. **确认项目信息**：项目名称、端类型（App/管理后台/全端）
2. **读取需求文档**：功能需求/PRD/会议纪要
3. **确认框架**：一级分支 + 详略策略，PM确认
4. **生成导图**：按本规范输出 .mm + .md 双格式
5. **质量检查**：对照检查清单逐项验证
6. **交付**：文件保存至项目目录 `03-思维导图/`
