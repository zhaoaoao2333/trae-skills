### 2.1 SPA导航架构规范 — 追加"父级映射模式"

在"5. 常见Bug预防"之后，追加：

```markdown
#### 替代方案：父级映射模式（推荐用于复杂原型）

> **来源**：Jam3a项目P008复盘。history栈机制在边界条件下容易出错（栈空、连续点击、深层返回跳页），改为pageParent父级映射后每个页面的返回目标明确可控。

**核心机制**：不使用pageStack历史栈，改为pageParent对象定义每个页面的明确父级。

**适用场景**：页面数量超过15页的复杂原型、多入口页面（同一页面可从多处进入）。

**实现要点**：

1. **定义父级映射表**

```javascript
// 每个页面的明确父级（页面ID → 父级页面ID）
const pageParent = {
  'game-detail': 'game-hall',
  'matching': 'game-detail',
  'game-result': 'matching',
  'profile': 'game-hall',  // 个人主页的父级是游戏大厅
  'settings': 'profile',
  // 一级页面无父级（返回时停留在当前页或回到首页）
  'game-hall': null,
  'arena': null,
};
```

2. **返回逻辑**

```javascript
function goBack(currentPageId) {
  const parent = pageParent[currentPageId];
  if (parent) {
    showPage(parent);
  } else {
    // 一级页面无父级，停留在当前页
    // 或回到首页
    showPage('game-hall');
  }
}
```

3. **优势对比**

| 维度 | history栈模式 | 父级映射模式 |
|------|-------------|------------|
| 返回目标 | 依赖栈顶，不确定 | 明确指定，可预测 |
| 连续点击返回 | 可能栈空报错 | 总是回到父级，不会出错 |
| 多入口页面 | 返回到上一个入口（可能非预期） | 返回到固定父级（符合用户心智） |
| 实现复杂度 | 需管理压栈/出栈 | 只需定义映射表 |
| 适用场景 | 简单线性流程 | 复杂多分支原型 |

4. **使用建议**
   - 页面数≤10页：history栈模式即可
   - 页面数>15页或有多入口页面：推荐父级映射模式
   - 两种模式不要混用
```

### 4.4 语言切换双入口规范（硬约束）

多语言项目中，语言切换功能必须在以下两个位置同时实现：

| 入口位置 | 实现方式 | 说明 |
|---------|---------|------|
| 页面外部浮动按钮 | 点击调用toggleLang() | 快捷切换，随时可用 |

> **案例依据**：Jam3a项目P008 V2版本语言切换按钮浮在页面外部与目录按钮重叠，V3修复为双入口后体验正常。

### 4.5 平铺版中文标签规范（硬约束）

平铺版所有页面标签必须使用中文名称：

| 页面ID | 正确标签 | 错误标签 |
|--------|---------|---------|
| onboarding | 引导页 | ~~onboarding~~ |
| register | 注册 | ~~register~~ |
| login | 登录 | ~~login~~ |
| home | 首页 | ~~home~~ |
| profile | 个人主页 | ~~profile~~ |

**规则**：
- 平铺版页面标签使用中文名，不用英文页面ID
- 页面ID仅用于代码层面（HTML id属性、JS函数参数）
- 页面目录导航也使用中文标签

> **案例依据**：Jam3a项目P008 V5质检脚本检测到平铺版标签问题，实际为脚本正则匹配问题，但规则本身正确——标签必须中文。

### 4.6 翻译从底层生成规范

**禁止**：对已生成的英文原型做简单字符串替换实现中文版本。

**正确做法**：
1. 从底层重新生成中文内容（在生成HTML时直接写入中文文案）
2. 建立完整的翻译映射表（如 `ZH_TO_EN_MAP`），覆盖所有文本节点
3. 翻译时使用TreeWalker遍历所有文本节点，逐个替换
4. 同步更新placeholder、title等属性的翻译

**原因**：
- 简单字符串替换容易遗漏（部分页面英文残留）
- 无法处理上下文相关的翻译（同一英文词在不同语境有不同中文含义）
- 从底层生成可确保翻译完整性

> **案例依据**：Jam3a项目P008 V2对英文原型做字符串替换导致部分页面英文残留，V3从底层重新生成中文内容（549条翻译映射）后翻译覆盖完整。

### 4.7 语言切换数据属性方案

推荐使用 `class="t"` + `data-zh` + `data-en` 属性方案实现语言切换：

```html
<span class="t" data-zh="快速开始" data-en="Quick Play">快速开始</span>
```

```javascript
function toggleLang() {
  const isToEn = currentLang === 'zh';
  document.querySelectorAll('.t').forEach(el => {
    el.textContent = isToEn ? el.dataset.en : el.dataset.zh;
  });
  currentLang = isToEn ? 'en' : 'zh';
}
```

**优势**：
- 每个双语元素自带翻译数据，不依赖外部映射表
- querySelectorAll批量更新，性能好
- 新增元素只需加class和data属性，无需维护映射表

> **案例依据**：Jam3a项目P008 V5使用此方案实现485个双语元素的中英切换，覆盖完整。
```

## 五、修改 `references/04-资源库/设计模式库.md`

在文件末尾追加2个新模式：

```markdown
---

## 模式15：父级映射返回模式（全行业通用）

**问题**：复杂原型（>15页）中，history栈返回逻辑容易出错（栈空报错、连续点击跳页、多入口返回非预期）？

**解决方案**：使用pageParent对象定义每个页面的明确父级，goBack()直接跳转父级页面。

**适用场景**：页面数>15页的复杂原型、多入口页面（同一页面可从多处进入）。

**示例**：
```javascript
const pageParent = {
  'game-detail': 'game-hall',
  'matching': 'game-detail',
  'game-result': 'matching',
  'profile': 'game-hall',
  'settings': 'profile',
  'game-hall': null,
};

function goBack(currentPageId) {
  const parent = pageParent[currentPageId];
  if (parent) {
    showPage(parent);
  } else {
    showPage('game-hall');
  }
}
```

**注意事项**：
- 一级页面父级设为null，返回时停留在当前页或回首页
- 多入口页面定义固定父级（选择最符合用户心智的主入口）
- 不要与history栈模式混用

## 模式16：分批生成模式（全行业通用）

**问题**：原型页面数量多（>20页），单次生成复杂度高、容易出错、问题定位困难？

**解决方案**：按优先级分批生成，每批独立生成和质检，最终组装为单HTML文件。

**适用场景**：页面数>20页的中大型原型项目。

**示例**：
```
生成流程：
├─ 第1批：P0核心页面（16页）
│   ├─ 独立脚本生成页面HTML
│   ├─ 即时质检（页面数/色彩/字体/交互）
│   └─ PM确认核心路径无问题
├─ 第2批：P1配套页面（18页）
│   ├─ 独立脚本生成页面HTML
│   ├─ 即时质检
│   └─ PM确认配套功能完整
└─ 组装阶段
    ├─ assemble脚本合并为单HTML文件
    ├─ 全链路校验（跳转/返回/交互闭环）
    └─ PM终审
```

**注意事项**：
- P0批次完成后需PM确认再生成P1
- 每批使用独立脚本，降低单次复杂度
- 组装时需处理CSS变量统一、JS函数合并、页面ID去重
```

## 模式17：自动化质检模式（全行业通用）

**问题**：原型生成后人工质检耗时且容易遗漏（色彩违规、字体违规、页面数量不符、语言切换覆盖率不足）？

**解决方案**：编写自动化质检脚本，对生成的HTML文件进行静态分析，输出质检报告。

**适用场景**：所有原型项目，特别是页面数>15页的中大型原型。

**示例**：
```javascript
// 质检脚本核心检查项
const checks = {
  // 1. 色彩违规检查
  colorViolations: () => {
    const allowedColors = ['#F7F7F7', '#333', '#666', '#999', '#CCC', '#D03030'];
    // 扫描所有CSS颜色值，找出不在允许列表中的色值
    // 排除游戏功能色（如棋盘四色）
  },
  // 2. 字体违规检查
  fontViolations: () => {
    // 检查是否使用了Google Fonts等外部字体引用
    // 仅允许系统字体（-apple-system, sans-serif等）
  },
  // 3. 页面数量检查
  pageCount: () => {
    // 统计HTML中page容器的数量，与PRD要求对比
  },
  // 4. 语言切换覆盖率检查
  langSwitchCoverage: () => {
    // 统计class="t"的元素数量，检查是否有遗漏的文本节点
  },
  // 5. 平铺版显示检查
  flatDisplay: () => {
    // 检查平铺版所有页面是否display:flex
    // 检查页面标签是否为中文
  },
};

// 输出质检报告
function runQualityCheck(htmlFilePath) {
  const results = Object.entries(checks).map(([name, fn]) => ({
    check: name,
    passed: fn().length === 0,
    issues: fn(),
  }));
  return results;
}
```

**注意事项**：
- 质检脚本应在原型生成后立即运行，不等验收员介入
- 色彩检查需排除游戏功能色等合理例外
- 平铺版标签检测需使用正确的正则匹配（中文字符范围）
- 质检报告作为验收员测试的辅助输入，不替代用户视角测试

> **案例依据**：Jam3a项目P008中编写自动化质检脚本检查色彩违规、字体违规、页面数量、语言切换等，有效提高质检效率。V5质检通过0色彩违规、0字体违规。
```
