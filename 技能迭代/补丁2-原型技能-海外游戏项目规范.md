## 一、两种原型形式的定义

- **平铺版（Tile Layout）**：所有页面同时展开展示，适合整体结构浏览、页面关系梳理、交付给开发理解全局
- **手机版（Mobile Simulation）**：模拟真实手机交互，单页面显示，适合体验流程、演示操作、用户测试

### 适用场景对比

| 场景 | 平铺版 | 手机版 |
|------|--------|--------|
| 需求评审 | 适合，一眼看全所有页面 | 不适合，需逐页切换 |
| 开发阅读 | 适合，快速定位目标页面 | 一般，需配合页面目录 |
| 交互演示 | 不适合，无页面切换效果 | 适合，完整模拟真实体验 |
| 用户测试 | 不适合，非真实使用场景 | 适合，接近真实App体验 |
| 设计走查 | 适合，对比多页面一致性 | 适合，检验单页面细节 |

### 版本命名规则
- **主版本**：V1、V2、V3...（重大结构调整）
- **子版本**：V3.1（平铺版）、V3.2（手机版）
- **迭代版本**：V3.2.1（小修复）、V3.2.2（功能调整）

### 2.3 页面标识规范
每个页面必须包含可视化标识：
- **页面序号**：左上角，格式"01"、"02"
- **页面名称**：序号下方，中文名称
- **页面ID**：可选，用于开发对应，如"page-home"
- **视觉区分**：相邻页面使用细边框或阴影区分

### 2.4 内容显示规则
- **强制显示**：所有`.page`元素必须可见，不可隐藏
- **滚动区域**：页面内滚动需正常生效，模拟真实手机滚动
- **固定元素**：顶部导航、底部Tab Bar保持在页面内固定位置
- **弹窗处理**：弹层/Toast默认不显示，或显示在对应页面内（非全局）

### 2.5 交互限制（平铺版特有）
- **无页面切换**：点击跳转类操作不做页面切换
- **Toast提示**：可显示，但只在对应页面区域内
- **弹窗/模态框**：限制在对应页面容器内，禁止全屏遮罩
- **页面导航**：提供页面目录侧边栏，点击后滚动到对应页面位置

### 3.4 导航实现规范

#### 底部Tab Bar
- **固定位置**：始终显示在一级页面
- **隐藏场景**：二级页面、全屏页面
- **切换逻辑**：点击切换页面，无返回历史
- **选中态**：图标+文字同时变色

#### 顶部导航栏
- **结构**：返回按钮（左）+ 标题（中）+ 操作按钮（右）
- **返回按钮**：非首页必显，支持逐级返回
- **标题**：当前页面名称

#### 页面目录（侧边栏）
- **触发方式**：悬浮按钮或右上角菜单
- **显示位置**：从右侧滑入
- **内容**：所有页面列表，点击跳转
- **关闭方式**：点击遮罩或关闭按钮

### 3.5 交互闭环要求
每个页面必须完成五问检验：
1. **从哪里来**：是否所有入口都有返回路径？
2. **当前是什么**：页面标题是否清晰？当前位置是否明确？
3. **到哪里去**：核心操作按钮是否醒目？
4. **操作后发生什么**：点击后是否有反馈（Toast/跳转/弹窗）？
5. **异常怎么处理**：网络错误、空数据、权限不足等异常态是否覆盖？

### 3.6 状态覆盖矩阵

| 状态 | 必需 | 说明 |
|------|------|------|
| 常规态 | 是 | 正常数据展示 |
| 空状态 | 是 | 无数据时的引导 |
| 加载中 | 是 | 骨架屏或loading |
| 错误态 | 是 | 网络错误、加载失败 |
| 成功态 | 条件 | 有操作后需要 |
| 权限受限 | 条件 | 有权限控制时需要 |

## 四、语言切换规范（多语言项目通用）

### 4.1 实现方式
- **方案A：双语内容预置**：HTML中同时包含中英文，通过CSS控制显示/隐藏
- **方案B：JavaScript动态替换**（推荐）：当前语言内容写入HTML，切换时动态替换文本

### 4.2 方案B实现示例
```javascript
const ZH_TO_EN_MAP = {
  "海湾第一游戏平台": "GULF'S #1 GAMING HUB",
  "玩。竞技。赢。": "Play. Compete. Win.",
};

function switchLanguage(lang) {
  if (lang === currentLang) return;
  const isToEn = lang === 'en';
  const map = isToEn ? ZH_TO_EN_MAP : EN_TO_ZH_MAP;
  
  const walker = document.createTreeWalker(
    document.body, NodeFilter.SHOW_TEXT, null, false
  );
  
  let node;
  while (node = walker.nextNode()) {
    let text = node.nodeValue;
    if (!text || text.trim() === '') continue;
    const keys = Object.keys(map).sort((a, b) => b.length - a.length);
    for (const key of keys) {
      if (text.includes(key)) {
        text = text.split(key).join(map[key]);
      }
    }
    node.nodeValue = text;
  }
  
  // 同步更新placeholder
  document.querySelectorAll('[placeholder]').forEach(el => {
    let ph = el.getAttribute('placeholder');
    const keys = Object.keys(map).sort((a, b) => b.length - a.length);
    for (const key of keys) {
      if (ph.includes(key)) {
        ph = ph.split(key).join(map[key]);
      }
    }
    el.setAttribute('placeholder', ph);
  });
  
  currentLang = lang;
  document.documentElement.lang = lang === 'zh' ? 'zh-CN' : 'en';
}
```

### 4.3 切换入口位置
- **设置页**：设置 > 通用 > 语言设置（主要入口）
- **首页**：可选，首页右上角快捷入口
- **引导页**：首次启动时的语言选择弹窗
- **排除位置**：平铺版不显示语言切换

## 五、翻译保护机制

翻译时必须保护以下内容不被翻译：
- HTML标签名和属性名（如`class`、`id`、`style`）
- CSS属性名和值关键字（如`display`、`flex`、`center`）
- JavaScript方法名和关键字（如`function`、`querySelectorAll`）
- 颜色代码（如`#0A0A1A`、`rgba(0,0,0,0.5)`）
- 页面ID和class名（如`page-home`、`active`）

### 关键保护代码
```python
def process_html_content(html):
    protected_blocks = []
    
    def protect_block(match):
        protected_blocks.append(match.group(0))
        return f'\x00BLOCK{len(protected_blocks)-1}\x00'
    
    html = re.sub(r'<style[^>]*>.*?</style>', protect_block, html, flags=re.DOTALL)
    html = re.sub(r'<script[^>]*>.*?</script>', protect_block, html, flags=re.DOTALL)
    
    parts = re.split(r'(<[^>]+>)', html)
    translated_parts = []
    
    for part in parts:
        if part.startswith('<') and part.endswith('>'):
            def translate_attr(m):
                attr_name = m.group(1)
                attr_val = m.group(3)
                if attr_name in ['placeholder', 'value', 'title']:
                    return f'{attr_name}={m.group(2)}{translate_text(attr_val)}{m.group(2)}'
                return m.group(0)
            part = re.sub(r'((?:placeholder|value|title)=(["\']))(.*?)(\2)', translate_attr, part)
            translated_parts.append(part)
        elif part.startswith('\x00BLOCK'):
            translated_parts.append(part)
        else:
            translated_parts.append(translate_text(part))
    
    html = ''.join(translated_parts)
    for i, block in enumerate(protected_blocks):
        html = html.replace(f'\x00BLOCK{i}\x00', block)
    
    return html
```

## 三、文化禁忌与合规

### 3.1 视觉元素禁忌
- 禁止出现猪、狗等动物形象（除非抽象化处理）
- 女性角色着装需符合伊斯兰规范（长袖、长裤/长裙）
- 避免使用十字架、六角星等宗教符号
- 禁止使用酒精、赌博（真实货币）相关暗示

### 3.2 色彩敏感度

**个人主页**：头像+段位 → 统计数据 → 游戏记录 → 装饰/成就

### 8.5.4 游戏特定设计原则

#### 色彩体系
- **主背景**：深色系优先（#0A0A1A、#121228），降低长时间游戏视觉疲劳
- **品牌色**：根据项目定位选择（如金色+紫色体现竞技荣誉感）
- **功能色**：成功绿/警告橙/错误红/信息蓝（全行业通用）

#### 交互规范
- **匹配等待**：实时显示匹配进度、预计等待时间、取消按钮
- **对局中**：禁止系统返回手势（防误触），提供"确认退出"二次确认
- **结算动画**：连胜特效、段位变化动画、奖励飞入效果
- **底部导航切换**：不支持滑动切换（防与游戏内手势冲突）

#### 组件特殊要求
- 游戏卡片需支持Hover上浮+发光效果
- 资产胶囊（金币/钻石余额）固定在顶部
- 段位徽章使用渐变色彩区分等级
- 匹配按钮需有脉冲动画吸引点击

### 8.5.5 性能要求

| 指标 | 标准 |
|------|------|
| 冷启动时间 | ≤ 3秒 |
| 页面切换 | ≤ 300ms |
| 游戏加载 | ≤ 5秒（首次）/ ≤ 2秒（缓存后） |
| 内存占用 | 前台≤ 500MB，后台≤ 100MB |
| 包体大小 | 初始下载≤ 100MB，资源按需下载 |

## 模式5：暗色品牌色模式（游戏专用）

**问题**：游戏类App需要营造竞技氛围，同时保证长时间使用不疲劳？

**解决方案**：深色背景为底，品牌色（金色/紫色）用于关键交互和选中态，发光效果克制使用。

**适用场景**：竞技游戏、游戏平台、电竞App。

**示例**：
```
色彩层级：
├─ 最底层：#0a0a0f（页面背景）
├─ 卡片层：#1a1a24（比背景亮一级）
├─ 输入层：#12121a（比卡片暗一级）
├─ 品牌色：仅用于主按钮、选中态、关键标签
└─ 发光效果：仅用于选中态、CTA按钮、稀有奖励
```

**注意事项**：
- 品牌色不做大面积背景色
- 发光效果不滥用，避免光污染
- 文字使用纯白色保证对比度

---

## 模式6：资产胶囊固定模式（游戏专用）

**问题**：游戏App中金币/钻石余额需要随时可见？

**解决方案**：在页面顶部固定资产胶囊栏，始终显示当前余额。

**适用场景**：有虚拟货币系统的游戏App。

**示例**：
```
顶部资产栏：
├─ 头像（点击→个人主页）
├─ 🪙 12,500（点击→充值中心）
├─ 💎 350（点击→商城）
└─ 🔔 通知（红点角标）
```

**注意事项**：
- 资产胶囊仅在一級页面显示
- 点击胶囊跳转对应功能页
- 余额变化需有数字滚动动画

---

## 模式7：匹配等待模式（游戏专用）

**问题**：游戏匹配需要等待，如何减少用户焦虑？

**解决方案**：匹配等待页显示脉冲动画+预计等待时间+取消按钮，匹配成功后显示对手信息弹窗。

**适用场景**：所有需要实时匹配的游戏。

**示例**：
```
匹配等待页：
├─ 脉冲圆环动画（雷达搜索效果）
├─ "匹配中..." 文字
├─ "预计等待 15s" 倒计时
├─ 取消按钮（幽灵按钮）
└─ 匹配成功 → 对手信息弹窗 + VS动画
```

**注意事项**：
- 匹配时间超过30秒需提示扩大搜索范围
- 取消匹配需即时响应
- 匹配成功后的动画不超过3秒

---

## 模式8：双形式原型模式（全行业通用）

**问题**：一份原型既要满足开发全局浏览，又要满足用户测试体验？

**解决方案**：生成平铺版（所有页面同时展示）和手机版（单页交互模拟）两种形式。

**适用场景**：所有需要原型交付的项目。

**示例**：
```
平铺版（V3.1）：
├─ 所有页面375×812并排展示
├─ 页面目录侧边栏导航
├─ 适合需求评审和开发阅读

手机版（V3.2）：
├─ 单页面全屏显示
├─ 完整页面跳转和返回
├─ 适合交互演示和用户测试
```

**注意事项**：
- 平铺版强制所有页面`display:flex !important`
- 手机版默认`display:none`，仅激活页`display:flex`
- 两种版本的HTML内容相同，仅CSS和JS不同
