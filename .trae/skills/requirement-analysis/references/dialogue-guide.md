# 对话引导策略

## 总则

对话的目标是：把 PM 脑中的模糊想法，逐步转化为清晰、完整、无矛盾的需求描述。

## 对话节奏

| 阶段 | 节奏 | 说明 |
|------|------|------|
| 开场 | 慢 | 让 PM 自由描述，AI 只听只记 |
| 梳理 | 中等 | AI 开始有针对性地提问，逐个确认 |
| 收敛 | 快 | 针对遗漏和矛盾快速确认，形成闭环 |

## 提问优先级

1. **先问结构**（端口、角色、流程）
2. **再问规则**（校验、约束、边界）
3. **最后问异常**（出错、超时、并发）

不颠倒顺序，因为异常处理依赖于正常流程的确认。

## 复述模板

每次 PM 描述完一个主题后，用以下模板复述确认：

```
我理解一下：
1. [要点1]
2. [要点2]
3. [要点3]

其中 [不确定的点] 我标注为待验证，你看对吗？
```

## 追问触发条件

以下情况必须追问：

| 触发条件 | 追问示例 |
|---------|---------|
| PM 描述中有矛盾 | "你刚才说A，但之前提到B，这两个怎么协调？" |
| 流程有断点 | "用户完成X之后，下一步是什么？" |
| 缺少异常处理 | "如果这个操作失败了，用户会看到什么？" |
| 角色权限不清 | "普通用户能看到这个信息吗？" |
| 数据来源不明 | "这个数据是从用户输入还是系统计算？" |
| 边界条件未提及 | "最多支持多少个？最少呢？" |

## 提问前自检规则 🚫

**每次提问前，必须先自问：这个问题的答案是否可以基于常识直接推导？**

### 禁止提问的场景

| 禁止场景 | 示例（不要问） | 正确做法 |
|---------|---------------|---------|
| 因果关系明确 | "数字码什么时候生成？"（支付后生成的常识无需问） | 直接采用常识结论：支付后自动生成 |
| 行业通用惯例 | "用户登录是否需要密码？" | 直接采用行业标准：需要 |
| 前后逻辑已隐含 | "退款后库存是否恢复？"（前面已说超时取消释放库存） | 根据已确认的逻辑推导 |
| 纯粹的操作细节 | "用户点击X后页面是否跳转？"（这是基本交互常识） | 按交互标准默认处理 |

### 自检三步法

1. **检查因果**：这个问题的答案是否被之前的逻辑链确定？
2. **检查常识**：这个问题的答案是否是本行业的通用做法？
3. **检查隐含**：这个问题的答案是否已被已确认的其他规则隐含推导？

**三步中任意一步为"是"→ 不提问，直接采用推导结论并在方案中标注 [常识推导]。**

### 违规记录

如果被 PM 指出问了不合理的问题（如"这还用问"），必须：
1. 立即记录到项目问题记录中
2. 总结规律并补充到本规则中
3. 后续对话中不得再犯同类错误

## 多方案呈现格式

不确定时，按以下格式呈现方案：

```
关于 [问题]，有以下方案：

方案A：[名称]
- 做法：[描述]
- 优点：[优点]
- 缺点：[缺点]
- 推荐度：⭐⭐⭐⭐⭐

方案B：[名称]
- 做法：[描述]
- 优点：[优点]
- 缺点：[缺点]
- 推荐度：⭐⭐⭐

请选择或提出你的想法。
```

## 对话结束标志

一个主题的对话可以结束，当：
- PM 明确表示"就这样的"
- 所有追问触发条件都不再满足
- AI 复述后 PM 确认无遗漏

## 行业规范反问机制

在对话过程中，AI 需要持续对照行业规范检查是否有遗漏板块。

### 反问时机

- 每个场景（流程梳理/功能细化）结束时
- PM 描述完一个完整主题后

### 反问模板

```
根据 [行业] 行业规范，通常还需要考虑以下模块：
- [模块A]
- [模块B]
- [模块C]

当前方案中未涉及这些内容，请问：
1. 这个项目需要包含哪些？
2. 哪些可以明确排除？
```

### 常见行业必要模块速查

| 行业 | 常见必要模块 |
|------|-------------|
| 通用 | 注册/登录、权限管理、消息通知、设置、帮助中心 |
| 电商 | 购物车、订单管理、支付、物流、售后、评价 |
| 内容社区 | 内容发布、审核机制、举报、推荐、关注/粉丝 |
| 企业服务 | 组织管理、角色权限、操作日志、数据导入导出 |
| 金融 | 实名认证、资金账户、交易记录、风控、合规 |
| 教育 | 课程管理、学习记录、考试测评、证书 |
| 医疗 | 挂号、问诊、处方、病历、隐私授权 |
| 社交 | 好友关系、即时消息、动态/朋友圈、隐私设置 |
| O2O | 商家管理、服务预约、评价退款、定位 |

### 处理结果

- PM 确认需要 → 补充到方案中，继续细化
- PM 确认不需要 → 标注 [已排除]，记录排除原因
- PM 不确定 → 标注 [待PM确认]，列入待确认清单
