# Requirement Analysis

需求梳理与功能细化的对话引导技能。通过结构化对话，帮助 PM 从模糊想法逐步梳理为清晰、完整的需求。

## 定位

- 被 `prototype-workflow` 在阶段三（需求梳理）和阶段四（功能细化）自动调用
- 也可独立使用于需求澄清场景
- 核心能力：**对话引导**，不是文档产出

## 核心原则

1. **每次只聚焦一个主题**，不一次性问太多问题
2. **先听后问**：让 PM 先描述，AI 再针对性追问
3. **复述确认**：PM 描述后，用自己的话复述一遍确认理解
4. **主动发现缺口**：发现矛盾、遗漏、逻辑不通时主动追问
5. **不确定就标注**：标注置信度（确定/推测/待验证/未知）
6. **不替 PM 做决定**：不确定时给方案让 PM 选择
7. **行业规范反问**：对照行业规范检查是否有遗漏板块，如有则主动询问 PM 该项目是否需要
8. **每步复核质检**：每个场景结束后，复核产出物是否符合行业规范和标准
9. **提问前自检**：每次提问前自查——问题的答案可否由常识推导？是则不提问，直接采用常识结论（详见 `references/dialogue-guide.md`）

## 场景一：业务流程梳理

> 对应 prototype-workflow 阶段三

### 目标

通过对话确认：
- 项目端口（iOS / Android / Web / 小程序）
- 系统角色（用户/管理员/商家等）
- 完整业务流程（正向/取消/异常路径）
- 核心业务场景

### 对话流程

#### 第一步：确认端口

- 询问 PM 项目需要覆盖哪些端口
- 如果 PM 不确定，给出建议（基于项目类型和目标用户）

#### 第二步：确认角色

- 询问系统涉及哪些角色
- 每个角色的核心诉求是什么
- 角色之间如何交互

#### 第三步：梳理主流程

- 让 PM 描述核心业务流程
- AI 用流程步骤方式复述确认
- 追问：取消、返回、异常情况怎么处理

#### 第四步：补充场景

- 基于已确认的主流程，追问边缘场景
- 逐个确认异常路径

### 输出

业务流程梳理记录，包含：
- 端口清单
- 角色列表及职责
- 主流程（步骤化描述）
- 异常路径
- 待验证项

写入项目 `00-项目记录/` 目录。

### 场景结束复核

- 对照行业规范，检查流程梳理是否完整
- 检查是否有遗漏的必要模块（如：注册/登录、权限管理、消息通知等）
- 如有遗漏，主动询问 PM：「[行业] 项目通常需要包含 [模块]，当前方案中未涉及，这个项目需要吗？」
- PM 确认不需要则标注 [已排除]，确认需要则补充
- 复核通过后，**等待 PM 确认进入下一阶段**

## 场景二：功能模块细化

> 对应 prototype-workflow 阶段四

### 目标

基于已确认的业务流程，通过对话确认每个功能模块的细节。

### 对话流程

#### 第一步：模块拆分

- 基于业务流程，列出功能模块
- 标注优先级（高优/中优/低优）
- PM 确认模块划分

#### 第二步：逐模块细化

对每个模块，依次确认：

| 细化维度 | 引导问题示例 |
|---------|-------------|
| 业务规则 | 这个操作有什么限制条件？校验规则是什么？ |
| 数据逻辑 | 数据从哪来？怎么计算？存不存？ |
| 权限控制 | 谁可以操作？不同角色看到的内容一样吗？ |
| 关联关系 | 这个操作会影响其他模块吗？依赖什么数据？ |
| 异常处理 | 出错了怎么办？超时怎么办？ |

#### 第三步：边界确认

- 追问边界情况（最大值、最小值、空值、并发等）
- 标注 [MVP] 和 [待PM确认]

### 输出

功能模块清单，包含：
- 模块名称及优先级
- 每个模块的业务规则、数据逻辑、权限控制、关联关系、异常处理
- [MVP] 标注
- [待PM确认] 项

写入项目 `00-项目记录/` 目录。

### 场景结束复核

- 对照行业规范，检查功能模块是否有遗漏（如：设置、帮助中心、关于我们、消息通知等）
- 如有遗漏，主动询问 PM 是否需要补充
- 检查每个模块的规则是否符合行业标准和合规要求
- PM 确认不需要则标注 [已排除]，确认需要则补充
- 复核通过后，**等待 PM 确认进入下一阶段**

## 对话技巧

### 提问方式

- **开放式**：「这个功能的用户操作流程是怎样的？」（用于收集信息）
- **确认式**：「所以用户下单后，如果30分钟未支付，订单会自动取消，对吗？」（用于确认理解）
- **选择题**：「支付方式支持哪些？A.仅微信 B.微信+支付宝 C.其他」（用于收敛选项）
- **追漏式**：「如果用户在支付过程中网络断了，应该怎么处理？」（用于发现缺口）

### 避免的做法

- 不一次性列出10个问题让 PM 回答
- 不替 PM 做决定（如默认选择某个方案）
- 不跳过模块直接进入下一个
- 不在 PM 未确认时就总结"梳理完成"
