# 思维导图生成技能

从需求沟通到产物交付的完整流程。分五阶段执行：项目初始化 → 背景了解 → 需求梳理 → 思维导图生成 → 交付与经验沉淀。

---

## 核心原则

1. **PM 驱动**：任何环节 PM 未确认，禁止进入下一步。AI 不替 PM 做决定。
2. **主 Agent 只决策审核，不动手**：思维导图由思维导图Agent产出。
3. **先理解再动手**：收到需求先复述、做完整性检查，PM 确认后才开始。
4. **防幻觉**：标注置信度（确定/推测/未知），不编造数据。不确定内容标注 `[待确认]`，不编造空节点。
5. **断点续传**：每次确认写记录到上下文记忆文件，上下文断了可无缝恢复。
6. **结构先行**：先确认一级框架和详略策略，再展开完整导图。
7. **每步复核质检**：每个阶段/步骤结束后，必须复核产出物是否符合思维导图生成规范，发现偏差立即修正。
8. **行业规范反问**：对照行业规范检查是否有遗漏板块，如有则主动询问 PM 该项目是否需要。
9. **经验沉淀**：每次项目结束后，整理本次导图生成中的问题与经验，形成可复用的规则。

## 意图确认机制

> **目的**：解决"PM回复不明确时AI胡乱猜测、擅自行动"的问题。确保AI在弄清问题、明确意图之前绝不盲目动手。
> **适用范围**：主调度器AI、思维导图Agent。

### 无效信号清单（一律视为未确认）

| 信号类型 | 示例 | AI正确处理 |
|---------|------|-----------|
| 模糊回应 | "好的""嗯""行""知道了""先这样吧" | 视为未确认，追问："请确认我的理解是否正确..." |
| 转移话题 | 不回答当前问题，说别的事 | 视为未确认，拉回："关于刚才的XX问题，您还没确认..." |
| 提出新问题 | "那XX怎么办" | 视为未确认，先处理原问题："我们先确认当前问题，再讨论XX" |
| 沉默/无回复 | | 等待回复，不自动推进，不猜测 |
| 部分回应 | 只回答了多个问题中的一个 | 视为未确认，追问其余问题 |
| 情绪性回应 | "随便""都行""你看着办" | 视为未确认，给出2-3个方案请PM选择 |
| 反问/质疑 | "为什么要这样做" | 视为未确认，先解释再重新请求确认 |

### 有效确认信号（必须同时满足）

1. PM明确使用了确认词汇：**确认、可以、没问题、继续、下一步、通过、就这样**
2. PM的回复**直接回应了AI当前提出的问题/方案**
3. PM的回复**没有歧义**，只有一种合理解读

### 行动前意图检查三问

AI每次准备行动前，必须自检：

**第一问：我理解了什么？**
- 用自己的话复述对PM意图的理解
- 如果理解有多种可能，列出所有可能的理解，请PM选择

**第二问：PM确认了吗？**
- 检查PM的上一条回复是否属于"有效确认信号"
- 如PM回复属于"无效信号清单"中的任意一项 → 停止行动，重新澄清

**第三问：我的理解有歧义吗？**
- 是否存在多种执行方式？
- 如有歧义，给出2-3个方案供PM选择，标注推荐和理由
- **禁止在歧义未消除前擅自选择方案执行**

### 模糊回复处理流程

```
PM回复模糊/不明确
  ↓
AI停止当前所有操作
  ↓
AI向PM输出《意图澄清请求》：
  - 我的当前理解是：...
  - 但我发现您的回复可能存在以下理解方式：
    A. ...
    B. ...
    C. ...
  - 请确认是哪种，或补充说明您的意图
  ↓
等待PM明确回复
  ↓
PM回复明确 → 继续执行
PM仍模糊 → 再次澄清（最多3轮）
```

### 修改方案确认流程

用户明确要求修改时，执行规则如下：

1. **生成方案后必须等待确认**
   - AI输出修改方案概要（修改内容 + 修改原因 + 预期效果）
   - 明确询问PM："以上方案是否确认？确认后我将执行修改"
   - **未获得PM明确确认前，禁止执行任何修改操作**

2. **方案概要格式**
   ```
   ## 修改方案概要

   | 序号 | 修改位置 | 修改内容 | 修改原因 | 预期效果 |
   |------|---------|---------|---------|---------|
   | 1 | ... | ... | ... | ... |

   **请确认以上方案后，我将执行修改。**
   ```

## 下一步操作引导机制

> **目的**：解决"主Agent跳流程、子Agent未调用就推进"的问题。在每个关键节点，自动调用必须调用的子Agent，报告结果，然后输出标准化引导菜单请PM选择下一步。
> **适用范围**：主调度器AI在所有关键节点结束后必须执行。

### 核心流程

每个关键节点：
1. **自动执行必须调用的子Agent** → 执行完成后报告结果
2. **对可选操作** → 列出可选项请PM选择
3. **禁止主动跳过引导菜单直接进入下一节点**

### 输出格式模板

```
## [当前步骤名称] 已完成

### 自动执行情况
- 已自动调用 **{子Agent名称}** 执行 {任务名称}
- **执行结果摘要**：{一句话概括子Agent输出}

### 下一步操作（请选择）
1. **[推荐] 进入下一阶段（{阶段名称}）**
2. 调用{子Agent名称}重新执行当前步骤
3. 返回修改当前步骤
4. 其他操作（请说明）
```

### 5个关键节点引导表

| # | 节点位置 | 完成内容 | 自动调用子Agent？ | 引导选项 |
|---|---------|---------|-----------------|---------|
| 1 | 阶段一结束 | 输出目录已创建，上下文记忆已初始化 | 无 | ①进入阶段二背景了解 |
| 2 | 阶段二结束 | 背景了解完成，行业规范已检查 | 无 | ①进入阶段三需求梳理 ②调整背景信息 |
| 3 | 步骤3.4完成 | PM反馈已处理，框架已补充完善 | 无 | ①进入需求确认(3.5) ②重新输出问题清单 ③调用思维导图Agent预览 |
| 4 | 步骤3.5结束 | 需求确认完成，无遗留待确认项 | 无 | ①进入阶段四思维导图生成 ②返回修改框架 |
| 5 | 步骤4.3完成 | 质量检查通过，产物已生成 | 无 | ①进入阶段五交付与经验沉淀 ②返回修改导图 |

## 阶段一：项目初始化

### 步骤 1.1 — 确认产出物保存位置

- 确认产出物保存位置（项目目录下的 `03-思维导图/` 或用户指定位置）
- 创建输出目录（如不存在）
- 初始化上下文记忆文件（`context-memory.md`，记录项目主题、背景要点、阶段进展）
- 将保存路径记入上下文记忆文件

**输出**：输出目录路径 + 上下文记忆文件路径

**等待 PM 确认**

---

## 阶段二：背景了解

### 步骤 2.1 — 项目背景描述

- PM 简述项目背景（或思维导图的使用场景）
- AI 倾听并记录，**不急着输出任何结构或导图**
- 仅做简单的理解确认，如：「了解了，这是一个 [一句话概括] 的项目/场景」

**此阶段不做深度分析，只为后续梳理建立基本认知。**

### 步骤 2.2 — 行业规范检查

- 对照行业规范，检查是否有遗漏的板块
- 根据项目类型（电商/SaaS/内容社区/企业服务等）识别常见板块
- 如有遗漏，主动询问 PM：「行业规范中通常包含 [板块名称]，这个导图需要包含吗？」

**阶段结束复核**：
- 对照行业规范，检查是否有遗漏板块
- 复核通过后，**等待 PM 确认进入下一阶段**

---

## 阶段三：需求梳理

> 此阶段核心目标：基于PM提供的输入材料，AI整理思维导图框架，输出待确认问题清单，PM确认后补充完善。**所有待确认问题必须在阶段三内解决，不得带入阶段四。**
>
> **关键流程**：接收输入 → AI整理框架 → 输出问题清单 → PM确认 → 补充完善 → 需求确认

### 步骤 3.1 — 接收输入

- AI主动询问PM提供输入材料（需求描述/功能清单/PRD/会议记录/零散想法）
- **如PM提供了材料**：AI接收并逐条理解
- **如PM未提供材料**：PM直接描述需求或想法，AI记录并整理
- AI复述确认：「我理解的输入内容如下，请确认是否有遗漏或理解错误」

**输出**：确认后的输入摘要（写入上下文记忆文件）

---

### 步骤 3.2 — AI整理思维导图框架

- 基于**确认的输入** + **阶段二背景**，AI整理思维导图框架
- 输出内容包含：
  - **核心主题**：一句话明确导图的核心主题
  - **一级分支预览**：3-6个一级分支，每个分支附一句话说明
  - **详略策略**：哪些分支详细展开（3-4级），哪些简要处理（1-2级）
  - **场景模板选择**：匹配最合适的场景模板（功能清单/业务流程/页面信息架构/用户旅程/竞品分析/会议纪要）
- **导向模式选择**：根据输入材料判断使用功能导向还是页面结构导向
  - 功能导向（默认）：适用于功能清单梳理、业务流程整理
  - 页面结构导向：适用于页面架构设计、原型设计输入源、页面跳转关系梳理
  - 在框架输出中标注所选导向模式，PM确认后生效
- 标注不确定点：
  - `[待确认]`：需要PM确认的内容
  - `[AI假设]`：AI基于常识做的假设，需PM确认
  - `[行业惯例]`：按行业通用做法处理，可后续调整

**输出**：思维导图框架初稿（写入上下文记忆文件）

---

### 步骤 3.3 — 输出待确认问题清单

> **关键步骤**：AI审查框架，主动暴露理解中的问题，让PM有针对性地确认。

**AI识别以下问题类型**：

| 类型 | 说明 | 示例 |
|------|------|------|
| **模糊点** | 描述不清晰，有多种理解方式 | "用户管理"是指后台管理还是用户自己管理个人信息？ |
| **矛盾点** | 模块间逻辑冲突或输入信息不一致 | 既要简洁又要详细展开所有子功能 |
| **遗漏点** | 缺少必要板块或环节 | 电商项目中缺少支付和售后模块 |
| **待决策** | 需要PM决策的结构划分方式 | 一级分支按端口分还是按功能域分？ |
| **边界点** | 边界条件不明确 | 是否需要包含技术架构层面的内容？ |

**输出要求**：
- 按优先级排序：高（阻塞结构）/ 中（影响分支）/ 低（细节优化）
- 每个问题包含：问题描述、AI当前理解、影响范围、建议确认方向
- 输出：《待确认问题清单》

---

### 步骤 3.4 — 补充完善框架

- PM提供反馈（按问题编号逐一）
- AI根据反馈更新框架

**反馈类型处理**：

| 结论类型 | AI处理方式 |
|---------|-----------|
| **已确认** | 按确认内容更新框架，标记`[已确认]` |
| **待进一步确认** | 保留原问题，补充新发现的问题，输出《待确认问题清单V2》 |
| **PM也未确定** | 标注`[需PM决策]`，给出2-3个方案供PM选择（含优缺点和推荐度） |

**循环机制**：
- 如产生新问题或高优先级问题未解决 → 回到步骤3.3，输出新版问题清单
- **循环直至无遗留待确认项（含高/中/低优先级），方可进入步骤3.5**

**输出**：完善的思维导图框架（写入上下文记忆文件）

---

### 步骤 3.5 — 需求确认与场景细化

- 基于**完善的框架**，AI与PM确认以下内容：
  - 核心主题是否准确
  - 一级分支划分方式是否合理
  - 详略策略是否符合预期
  - 标注规范是否清楚（`[待确认]`/`[AI补充]`/`（略）` 等）

**对话策略**：
- 每次只聚焦一个主题，不一次性问太多
- PM描述后，AI用自己的话复述确认
- 发现矛盾或遗漏时主动追问
- 不确定的内容标注 `[待验证]`

**输出**：确认的思维导图框架（一级分支 + 详略策略 + 场景模板选择）

**阶段结束复核**：
- 对照思维导图生成规范，检查框架是否符合规则
- **检查待确认问题清单：确认所有问题已解决，无遗留待确认项**
- 复核通过后，**等待 PM 确认框架完整**

## 阶段四：思维导图生成

> 此阶段调用 `references/01-Agent定义/思维导图Agent.md`（思维导图Agent）主导执行。
> 加载 `references/03-规则规范/思维导图生成规范.md`（全部规则）。
> 加载 `references/02-模板文件/思维导图模板.md`（输出格式模板和场景骨架）。

### 步骤 4.1 — 结构确认（强制）

- 输出完整的一级框架 + 详略策略 + 场景模板选择
- 遵循 `references/02-模板文件/思维导图模板.md` 中的"结构确认模板"格式
- **等待 PM 确认后，方可展开完整导图**
- 如选定页面结构导向模式：
  - 加载 `references/03-规则规范/页面结构导向思维导图规范.md`
  - 确认端类型（App端/管理端/全端）
  - 先输出页面清单，PM确认后展开板块

---

### 步骤 4.2 — 展开内容

- 按确认的结构和详略策略，输出完整的思维导图
**生成模式**：
- **逐层生成（默认）**：先输出一级框架，PM确认后逐层展开子级节点
- **一次性完整版**：当PM要求"一次性生成完整版""直接输出完整导图"时，以功能和需求为导向，忽略层级限制，该拆分就拆分，直接输出完整导图
- 输出双格式：
  - **主文件：FreeMind (.mm)** — XML 格式，WPS / XMind / MindManager / Freeplane / ProcessOn 均可导入
  - **备份文件：Markdown (.md)** — 无序列表格式，便于直接阅读
- 自动补充行业通用模块（标注 `[AI补充]`，不超过总节点数的 20%）
- 不确定内容标注 `[待确认]`
- 导图末尾附说明："AI补充节点X个，待确认节点X个。"

---

### 步骤 4.3 — 质量检查

> 自动执行自检，不通过则修复后重新自检。

**自检清单**：

| # | 检查项 | 检查标准 |
|---|--------|---------|
| 1 | 层级完整性 | 不设上限，每个子节点必须属于其父节点的逻辑范畴 |
| 2 | 节点文字 | 每个节点15字以内，无模糊表述 |
| 3 | 逻辑并列 | 同层级节点属于同一逻辑范畴，无包含关系 |
| 4 | 详略区分 | 详细展开区域3-4级，简要处理区域1-2级，有明显区分 |
| 5 | AI补充标注 | 所有AI补充节点均标注 `[AI补充]`，占比不超过20% |
| 6 | mm文件可导入性 | XML格式正确，可被思维导图工具正常导入 |
| 7 | 结构完整性 | 一级分支覆盖核心主题全部范围，无遗漏 |
| 8 | 子节点数量 | 每个父节点下子节点2-5个 |
| 9 | 节点无重复 | 不同节点间无重复或高度相似表述 |
| 10 | 标注规范 | `[待确认]`/`[AI补充]`/`（略）` 使用正确 |
| 11 | 导向模式一致性 | 如为页面结构导向，检查唯一入口规则、跳转格式、交互描述、状态覆盖 |
| 12 | mm文件编码 | 如为页面结构导向，检查XML编码为UTF-8 |
