# 思维导图生成规范

> 本文件定义思维导图生成的全部规则。思维导图Agent和所有涉及导图输出的场景必须遵守本规范。
> 具体输出格式参见 `references/思维导图模板.md`。

---

## 一、核心原则

1. **逻辑一致**：同级节点必须属于同一逻辑范畴。按端口分就全部按端口分，按功能域分就全部按功能域分，不能混用。
2. **结构平衡**：每个父节点下的子节点数量大致均衡，避免某个分支特别庞大、另一个分支只有一个子节点。
3. **不限层级**：不设层级上限，允许逐层生成。以完整描述为目标，该拆分子级节点就拆分子级节点。当PM要求一次性生成完整版导图时，以功能和需求为导向，忽略层级限制，生成完整的思维导图。
4. **详略得当**：核心流程和关键功能详细展开到 3-4 级，辅助功能和字段类信息简要处理到 1-2 级。
5. **一键可用**：输出的内容可以直接导入思维导图工具，无需二次编辑。

---

## 二、主题与节点规范

### 核心主题

- 一个思维导图只有一个核心主题，放在第一行
- 使用"产品名+功能清单"或"产品名+业务流程"格式，如"电商平台产品功能清单"、"用户下单主流程"
- 必须是具体的、可界定的，不能是"一些想法"、"整理一下"这类模糊表述
- 互联网产品核心主题中建议标注产品类型，如"XX小程序功能清单"、"XX APP功能清单"

### 一级分支

- 数量 3-6 个，最多不超过 7 个。超过 7 个需要归纳合并
- 是对核心主题的完整分解，所有一级分支加起来必须覆盖核心主题的全部范围
- 之间是并列关系，不出现包含关系
- 互联网产品常用一级分支划分方式：
  - 按端口：用户端 / 商家端 / 平台运营端
  - 按功能域：交易域 / 商品域 / 用户域 / 营销域 / 内容域 / 数据域
  - 按阶段：售前 / 售中 / 售后（业务流程导图）
  - 按角色：用户 / 系统 / 管理员（后台产品）
  - 多端产品：通用功能 / 小程序特有 / APP特有 / H5特有

### 子节点

- 每个父节点下的子节点 2-5 个。少于 2 个考虑合并到上级，多于 5 个考虑拆分或分组
- 是对父节点的分解，不是举例、不是备注、不是描述
- 同一父节点下的所有子节点，加起来必须完整覆盖父节点的含义

---

## 三、节点表述规范

### 文字长度

- 每个节点控制在 15 字以内，超过需精简
- 用核心关键词表述，不用完整句子
- 示例："用户点击搜索框后系统展示搜索页面"→"点击搜索框→搜索页"

### 表述格式

| 类型 | 格式 | 示例 |
|---|---|---|
| 功能类 | 名词或动名词 | "商品管理"、"订单处理" |
| 流程类 | 动词+名词 | "提交订单"、"确认收货" |
| 状态类 | 名词+状态描述 | "支付成功"、"订单已取消" |
| 异常类 | 触发条件→处理方式 | "支付超时→自动取消" |
| 页面节点 | 页面名称（页面类型） | "商品列表（列表页）" |

页面类型包括：主页、列表页、详情页、表单页、结果页、弹窗、抽屉。

### 禁止表述

- 不用"XXX等"模糊结尾，用括号注明数量：`基本信息字段（4项）`
- 不用"包括但不限于"等法律用语
- 不用"可能""大概""也许"，不确定的标注 `[待确认]`
- 不用标点符号结尾（问号和引号除外）
- 节点之间不出现重复或高度相似的表述

---

## 四、层级与结构规范

### 层级控制

- 不设层级上限，以完整描述为目标
- 允许逐层生成：先输出一级框架，PM确认后逐层展开子级节点
- 一次性完整版：当PM要求一次性生成完整版导图时，以功能和需求为导向，该拆分的就拆分，不受层级限制
- 详细展开区域：深入到子级节点直至完整描述
- 简要处理区域：1-2级，用合并概括或标注"（略）"收住

### 结构校验（输出前自检）

- 每个节点是否都有父节点？不能有孤立节点
- 每个父节点是否至少有 2 个子节点？少于 2 个考虑合并到上级
- 每个父节点的子节点是否不超过 5 个？超过 5 个考虑拆分或分组
- 同一层级的所有节点是否逻辑并列？不能出现包含关系
- 所有子节点加起来是否完整覆盖父节点？不能有遗漏

---

## 五、详略控制规范

### 详细展开的内容（3-4 级）

- 主业务流程的每一步骤
- 核心功能模块的具体功能点
- 关键交互逻辑和状态变化
- 异常处理路径和分支条件
- PRD 中明确要求的功能点
- PM 在对话中反复强调或明确说"这个很重要"的内容

### 简要处理的内容（1-2 级或合并）

| 内容类型 | 处理方式 |
|---|---|
| 字段列表 | 合并概括加括号注明数量，如"基本信息字段（姓名、手机号等4项）" |
| 未确认需求 | 一个节点概括 + `[待确认]`，不展开空节点 |
| 辅助功能 | 设置、帮助、协议、关于等，合并到"系统设置"或"辅助功能"节点下 |
| 常规状态覆盖 | 主流程中已体现的不再逐页重复列出 |
| 低频边缘场景 | 合并为"其他异常场景"一个节点 |

### 简要处理的具体方式

- **合并概括**：同类节点合并，加括号注明数量
- **标注待确认**：`XXX [待确认]`，不空展开假节点
- **加略后缀**：节点后加`（略）`，表示此处有内容但当前不需展开
- **收拢为备注**：重要但偏离当前主题的内容，收拢为父节点的括号说明

### 详略判断标准

| 判断项 | 详细 | 简要 |
|---|---|---|
| 用户需要知道吗？ | 需要 | 不需要 |
| 是核心路径上的吗？ | 是 | 不是 |
| 是 PRD 中明确要求的吗？ | 是 | 不是 |
| 展开后能帮助理解吗？ | 能 | 不能 |
| 这个信息现在能确定吗？ | 能 | 标注 `[待确认]` |

## 六、互联网产品特定规范

### 产品类型识别（生成前必须识别）

| 产品类型 | 必须标注 | 必须展开的特有节点 |
|---|---|---|
| 小程序 | 平台属性（微信/支付宝/抖音） | 平台登录、消息订阅、分包加载、小程序码、审核相关（类目资质、隐私接口） |
| H5 | 部署环境（公众号内嵌/独立网页/混合APP内嵌） | 宿主环境：微信JSSDK、支付授权目录、分享能力、响应式适配 |
| APP | 区分 iOS/Android 双端 | 推送通知、应用权限、版本更新、应用商店审核、硬件权限申请流程 |
| 多端产品 | — | 第一层拆分"通用功能"和"端差异功能"，通用功能只写一次，不在每个端下面重复 |

### 导图结构约定

- 第一层：按角色或功能域划分，选一种贯穿始终，不混用
- 第二层：用户端按页面展开（首页/分类/购物车/我的/详情/订单），运营端按管理模块展开（商品/订单/用户/活动/数据），技术架构按服务模块展开（用户/商品/订单/支付/通知服务）
- 第三层及以下：按功能点展开。每个页面或模块下只列该页面特有的功能点。全局通用的功能如登录、消息通知，收拢到一个"公共能力"分支中

### 流程图约定

- 主流程只画用户完成核心任务的最短路径，分支细节在下一级展开
- 页面状态附加在对应功能节点上，格式：`功能点（含XX、XX状态）`
- 异常处理不独立成为一级分支，跟在主流程对应步骤后面，格式：`主步骤→异常处理（超时/失败/权限不足）`。超过 3 个子节点才考虑展开
- 多角色流程用 `【角色名】步骤描述` 标注，系统自动处理的步骤标注 `【系统】`

### 页面信息架构图约定

- 页面名称必须是 PRD 中正式定义的名称，同类页面命名格式统一
- 导航关系用父子层级表示：父节点是入口页面，子节点是目标页面
- 底部导航页面作为一级节点并列，页面内入口作为二级节点

## 七、标注规范

| 标注 | 含义 | 限制 |
|---|---|---|
| `[AI补充]` | AI 基于行业经验主动补充的节点 | 每张导图不超过总节点数的 20% |
| `[待确认]` | 需求中未明确、需要 PM 确认的节点 | 每张导图不超过 5 个 |
| `[MVP]` | 最小可行版本暂时不做的功能 | — |
| `（略）` | 此节点下有内容但当前不需展开 | — |
| `（共X项）` | 合并概括时括号注明总数 | — |
| `（XX/XX/XX状态）` | 页面或功能的状态，附在节点后面不单独开节点 | — |

## 九、输出流程

1. **确认结构**：输出一级框架 + 详略策略，等 PM 确认
2. **展开内容**：按确认的结构输出完整导图
3. **标注来源**：末尾附"AI补充节点X个，待确认节点X个"

---

## 十、生成模式

思维导图支持两种生成模式：

### 逐层生成模式（默认）

- 先输出一级框架，PM确认后逐层展开
- 每层展开后等待PM确认再继续下一层
- 适用于：大型项目、需要逐步确认的场景

### 一次性完整版模式

- 当PM明确要求"一次性生成完整版""直接输出完整导图"时启用
- 以功能和需求为导向，忽略层级限制
- 该拆分子级节点就拆分子级节点，以完整描述为目标
- 输出后附完整说明（AI补充节点数、待确认节点数）
- 适用于：PM已有明确需求、需要快速产出完整导图的场景

### 模式选择规则

| PM指令 | 生成模式 | 行为 |
|--------|---------|------|
| "先看框架" / "逐步展开" | 逐层生成 | 输出一级框架，等待确认 |
| "一次性生成" / "完整版" / "直接输出" | 一次性完整版 | 忽略层级限制，直接输出完整导图 |
| 未明确 | 逐层生成（默认） | 输出一级框架，等待确认 |

## 十一、页面结构导向规范（补充）

当PM要求"以页面结构为导向"生成思维导图时，以下规则**被页面结构导向规范覆盖**：

| 原规则（功能导向） | 页面结构导向规则 | 规范文件 |
|------------------|----------------|---------|
| 层级不超过4级 | 不限层级，以完整描述为目标 | 页面结构导向思维导图规范.md |
| 每节点15字以内 | 每节点25字以内 | 页面结构导向思维导图规范.md |
| 无跳转引用规则 | 唯一入口展开，非唯一入口写引用 | 页面结构导向思维导图规范.md |
| 无交互描述要求 | 核心页面需描述交互效果 | 页面结构导向思维导图规范.md |
| 无状态覆盖要求 | 核心页面需覆盖4种状态 | 页面结构导向思维导图规范.md |
| mm文件无编码要求 | mm文件必须UTF-8编码 | 页面结构导向思维导图规范.md |

**未覆盖的规则继续生效**：核心原则（逻辑一致/结构平衡/详略得当/一键可用）、主题规范、标注规范、AI补充限制、输出流程等。

完整页面结构导向规范见 `references/03-规则规范/页面结构导向思维导图规范.md`。
