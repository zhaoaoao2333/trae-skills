# 流程图生成技能

从需求沟通到流程图产物交付的完整流程。分五阶段执行，产物为 Mermaid 流程图源码（.mmd）+ Markdown 说明文件（.md）。

---

## 核心原则

1. **PM驱动**：任何环节 PM 未确认，禁止进入下一步。AI 不替 PM 做决定。
2. **先理解再动手**：收到需求先复述、做完整性检查，PM 确认后才开始。
3. **防幻觉**：标注置信度（确定/推测/未知），不编造数据。
4. **结构先行**：必须先输出结构确认，PM 确认后再展开完整内容。
5. **闭环原则**：流程路径必须有明确的起点和终点。
6. **产物可导入**：Mermaid 源码必须兼容 WPS 流程图导入。
7. **经验沉淀**：每次生成后整理问题与经验，形成可复用的知识积累。

---

## 意图确认机制

> **目的**：解决"PM 回复不明确时 AI 胡乱猜测、擅自行动"的问题。确保 AI 在弄清问题、明确意图之前绝不盲目动手。
> **适用范围**：主调度器AI、流程图Agent。

### 无效信号清单（一律视为未确认）

| 信号类型 | 示例 | AI正确处理 |
|---------|------|-----------|
| 模糊回应 | "好的""嗯""行""知道了""先这样吧" | 视为未确认，追问："请确认我的理解是否正确..." |
| 转移话题 | 不回答当前问题，说别的事 | 视为未确认，拉回："关于刚才的XX问题，您还没确认..." |
| 提出新问题 | "那XX怎么办" | 视为未确认，先处理原问题："我们先确认当前问题，再讨论XX" |
| 沉默/无回复 | | 等待回复，不自动推进，不猜测 |
| 部分回应 | 只回答了多问题中的一个 | 视为未确认，追问其余问题 |
| 情绪性回应 | "随便""都行""你看着办" | 视为未确认，给出2-3个方案请PM选择 |
| 反问/质疑 | "为什么要这样做" | 视为未确认，先解释再重新请求确认 |

### 有效确认信号（必须同时满足）

1. PM 明确使用了确认词汇：**确认、可以、没问题、继续、下一步、通过、就这样**
2. PM 的回复**直接回应了 AI 当前提出的问题/方案**
3. PM 的回复**没有歧义**，只有一种合理解读

### 行动前意图检查三问

AI 每次准备行动前，必须自检：

**第一问：我理解了什么？**
- 用自己的话复述对 PM 意图的理解
- 如果理解有多种可能，列出所有可能的理解，请 PM 选择

**第二问：PM 确认了吗？**
- 检查 PM 的上一条回复是否属于"有效确认信号"
- 如 PM 回复属于"无效信号清单"中的任意一项 → 停止行动，重新澄清

**第三问：我的理解有歧义吗？**
- 是否存在多种执行方式？
- 如有歧义，给出2-3个方案供 PM 选择，标注推荐和理由
- **禁止在歧义未消除前擅自选择方案执行**

### 模糊回复处理流程

```
PM回复模糊/不明确
  ↓
AI停止当前所有操作
  ↓
AI向PM输出《意图澄清请求》：
  - 我的当前理解是：...
  - 但我发现您的回复可能存在以下理解方式：
    A. ...
    B. ...
    C. ...
  - 请确认是哪种，或补充说明您的意图
  ↓
等待PM明确回复
  ↓
PM回复明确 → 继续执行
PM仍模糊 → 再次澄清（最多3轮）
```

### 修改方案确认流程

用户明确要求"每次修改方案要求确认"。执行规则如下：

1. **生成方案后必须等待确认**
   - AI 输出修改方案概要（修改内容 + 修改原因 + 预期效果）
   - 明确询问 PM："以上方案是否确认？确认后我将执行修改"
   - **未获得 PM 明确确认前，禁止执行任何修改操作**

2. **方案概要格式**
   ```
   ## 修改方案概要

   | 序号 | 修改位置 | 修改内容 | 修改原因 | 预期效果 |
   |------|---------|---------|---------|---------|
   | 1 | ... | ... | ... | ... |

   **请确认以上方案后，我将执行修改。**
   ```

3. **紧急修复例外**
   - P0 阻断性错误（如流程路径完全断开、语法错误导致无法导入）可先行修复
   - 修复后必须向 PM 报告："发现P0问题[XX]，已紧急修复，详情如下..."

## 触发条件

### 主流程触发

- 用户输入 `/flowchart`
- 用户说"生成流程图""帮我梳理流程图""画一个流程图""整理业务流程"
- 需求梳理阶段 PM 确认后需要输出流程图
- 主调度器根据 PM 指令调用

### 独立触发说明

> 独立触发时，直接调用 `references/01-Agent定义/流程图Agent.md`（流程图Agent），输出 .mmd + .md 双格式流程图文件。流程图Agent 具备上下文学习和主动反问能力，会自动读取项目已有文档，从零散输入中整理结构，有疑问时主动反问。

## 阶段一：项目初始化

> **目的**：确认输出位置、初始化上下文，为后续流程建立基础。

### 步骤 1.1 — 确认产出物保存位置

- 确认产出物保存到项目目录还是 PM 指定的其他位置
- 如在项目中，保存到对应项目目录下
- 如为独立任务，创建输出目录

### 步骤 1.2 — 创建输出目录

- 创建标准输出目录结构（如需要）
- 确认目录可访问、可写入

### 步骤 1.3 — 初始化上下文记忆

- 记录本次任务的基本信息：触发方式、PM 身份、项目关联（如有）
- 如有关联项目，自动读取项目已有文档建立上下文

### 步骤 1.4 — PM 确认

- 输出初始化结果摘要
- 等待 PM 确认后进入阶段二

**输出格式**：
```
## 阶段一：项目初始化 已完成

- 产出物保存位置：{路径}
- 输出目录：{路径}
- 关联项目：{项目名称或无}
- 上下文状态：已初始化

**请确认以上信息，确认后进入阶段二（背景了解）。**
```

---

## 阶段二：背景了解

> **目的**：建立对项目/业务的基本认知，为需求梳理提供语境基础。

### 步骤 2.1 — 项目背景描述

- PM 简述项目/业务背景
- AI 倾听记录，简单理解确认
- **不做深度分析**，只为后续梳理建立基本认知
- 如有关联项目，AI 自动补充已知的背景信息

**AI 输出**：
```
## 背景理解确认

我的理解：
- 项目/业务：{一句话概括}
- 核心场景：{关键场景}
- 涉及角色：{已识别的角色}

以上理解是否准确？有补充请告诉我。
```

### 阶段结束复核

- 对照行业规范检查是否有遗漏板块（如：是否涉及支付/审批/多角色协作等常见场景）
- 如发现疑似遗漏，主动询问 PM

**输出格式**：
```
## 阶段二：背景了解 已完成

### 背景摘要
- 项目/业务：{概括}
- 核心场景：{场景}
- 涉及角色：{角色}
- 行业规范检查：{有无遗漏}

**请确认背景理解是否准确，确认后进入阶段三（需求梳理）。**
```

---

## 阶段三：需求梳理

> **目的**：将 PM 的输入转化为结构清晰的流程框架，确保理解一致后再进入生成阶段。

### 步骤 3.1 — 接收输入

- AI 询问 PM 提供输入材料：业务描述 / PRD / 场景描述 / 零散想法均可
- AI 接收并逐条理解
- AI 复述确认，确保理解无误
- 如有关联项目，自动读取项目已有文档补充上下文

**输出**：
```
## 输入确认摘要

我收到的输入材料：
1. {输入1概述}
2. {输入2概述}
3. ...

我的理解：
- 核心流程：{一句话概括}
- 关键环节：{关键步骤}
- 涉及角色：{角色列表}

以上理解是否正确？有补充或修正请告诉我。
```

### 步骤 3.2 — AI 整理流程框架

- 基于确认的输入 + 背景，AI 整理流程框架
- 输出内容：
  - **流程名称**：该流程图的名称
  - **流程类型**：泳道图 / 序列图 / 状态流转图
  - **涉及角色**：各角色及其在流程中的职责
  - **路径概览**：正向路径 + 主要分支 + 异常路径
  - **起点/终点**：流程从哪里开始、到哪里结束
- 标注不确定点：
  - `[待确认]` — 需要 PM 确认
  - `[AI假设]` — AI 根据上下文推断，需验证
  - `[行业惯例]` — 按行业通用做法处理，PM 可调整
- **多角色流程必须使用泳道图**

**输出格式**：
```
## 流程框架初稿

【流程名称】：{名称}

【流程类型】：{泳道图 / 序列图 / 状态流转图}

【涉及角色】：
- {角色1}：{职责描述}
- {角色2}：{职责描述}
- {角色3}：{职责描述（如有）}

【路径概览】：
- 正向路径：{角色}→{步骤}→{步骤}→...→{完成}
- 主要分支：[{条件A}→{处理A}]、[{条件B}→{处理B}]
- 异常路径：[{超时}→{处理}]、[{失败}→{处理}]

【流程起点】：{起点描述}
【流程终点】：{终点描述}

### 不确定点标注
- [待确认] {不确定内容1}
- [AI假设] {假设内容1}
- [行业惯例] {行业通用做法1}

以上框架是否准确？有调整请告诉我。
```

### 步骤 3.3 — 输出待确认问题清单

- AI 审查流程框架，主动暴露问题
- **问题类型**：
  - 模糊点 — 描述不清、可被多种方式理解
  - 矛盾点 — 前后描述不一致
  - 遗漏点 — 流程中缺失的环节或角色
  - 待决策 — 多种合理方案，需要 PM 选择
  - 边界点 — 流程起止范围不明确
- **识别信号**：
  - 模糊词汇（"大概""可能""应该""好像"）
  - 缺失的异常处理路径
  - 角色职责不清晰的环节
  - 流程路径断头（有起点无终点或反之）
- 按优先级排序（高/中/低）

**输出格式**：
```
## 待确认问题清单

### 高优先级（影响流程整体结构）
| 序号 | 类型 | 问题描述 | 建议方案 | AI推荐 |
|------|------|---------|---------|--------|
| 1 | {类型} | {问题} | {方案A / 方案B} | {推荐方案} |

### 中优先级（影响分支细节）
| 序号 | 类型 | 问题描述 | 建议方案 | AI推荐 |
|------|------|---------|---------|--------|

### 低优先级（影响边缘场景）
| 序号 | 类型 | 问题描述 | 建议方案 | AI推荐 |
|------|------|---------|---------|--------|

请逐一确认或补充说明。
```

### 步骤 3.4 — 补充完善流程

- PM 提供反馈后，AI 更新流程框架
- 已确认项 → 更新标记为 `[已确认]`
- 待进一步确认 → 输出 V2 版本框架
- PM 也未确定 → 给出2-3个方案，标注推荐和理由，请 PM 选择
- 循环执行直至无遗留待确认项

**输出格式**：
```
## 流程框架 {版本号}

（更新后的框架内容）

### 确认状态
- ✅ [已确认] {已确认内容1}
- ✅ [已确认] {已确认内容2}
- ⏳ [待确认] {待确认内容（如有）}

还有待确认项吗？全部确认后进入下一步。
```

### 步骤 3.5 — 需求确认与场景细化

- AI 与 PM 确认以下关键要素：
  - 流程类型（泳道图/序列图/状态流转图）
  - 涉及角色及泳道划分方式
  - 异常覆盖范围（需覆盖哪些异常场景）
  - 关键业务规则（超时时间、重试策略、边界条件等）
- 发现矛盾或遗漏时主动追问

**输出格式**：
```
## 需求确认汇总

- 流程类型：{确认结果}
- 涉及角色：{确认结果}
- 泳道划分：{确认结果（如适用）}
- 异常覆盖：{确认结果}
- 关键业务规则：{确认结果}

以上确认无误后，进入阶段四（流程图生成）。
```

## 阶段四：流程图生成

> **目的**：基于确认的流程框架，生成完整的 Mermaid 流程图产物。

### 步骤 4.1 — 结构确认（强制）

- 输出流程名称 + 类型 + 角色 + 路径概览 + 起点/终点
- 确认格式遵循 `references/02-模板文件/流程图模板.md` 中的"结构确认模板"
- **必须等待 PM 确认后才能展开完整流程图**

**输出格式**：
```
## 结构确认（生成前最终确认）

【流程名称】：{名称}
【流程类型】：{类型}
【涉及角色】：{角色列表}
【路径概览】：{路径描述}
【流程起点】：{起点}
【流程终点】：{终点}

以上结构是否准确？确认后我将展开完整流程图。有调整请告诉我。
```

### 步骤 4.2 — 展开流程

- 调用 `references/01-Agent定义/流程图Agent.md`（流程图Agent）执行生成
- 输出 `.mmd` + `.md` 双格式文件
- 生成规则遵循 `references/03-规则规范/流程图生成规范.md`
- 模板格式遵循 `references/02-模板文件/流程图模板.md`
- **多角色流程**：使用泳道图（`graph TD` / `graph LR` + `subgraph`）
- **单角色流程**：使用标准序列结构
- 自动补充异常分支（标注 `[AI补充]`，补充节点不超过总节点数的 20%）
- 不确定内容标注 `[待确认]`

### 步骤 4.3 — 质量检查

- 自检清单：
  - [ ] 路径闭环：所有路径从起点到终点，无断头路
  - [ ] 断头路检查：每个节点都有入边和出边（终点除外）
  - [ ] 异常覆盖：超时/失败/权限/中断/边界异常是否全部覆盖
  - [ ] 泳道交互标注：跨泳道箭头是否用虚线并标注内容
  - [ ] 节点文字：每个节点文字是否在20字以内，表述是否精简
  - [ ] Mermaid 语法：语法是否正确，WPS 可导入
- **不通过则修复后重新自检，直到全部通过**

**输出格式**：
```
## 质量检查结果

- [x] 路径闭环：通过
- [x] 断头路检查：通过
- [x] 异常覆盖：通过
- [x] 泳道交互标注：通过
- [x] 节点文字：通过
- [x] Mermaid 语法：通过（WPS可导入）

质量检查全部通过。产物已保存至：{路径}
```

## 阶段五：交付与经验沉淀

> **目的**：交付最终产物，整理本次生成过程中的经验和问题。

### 步骤 5.1 — 交付产物

- 交付内容：
  - `.mmd` 文件 — Mermaid 源码（可直接导入 WPS）
  - `.md` 文件 — Markdown 说明文件（包含流程说明、角色职责、分支解释）
  - 质量检查结果

**输出格式**：
```
## 交付产物

| 文件 | 格式 | 说明 |
|------|------|------|
| {文件名}.mmd | Mermaid源码 | 可直接粘贴到WPS流程图导入 |
| {文件名}.md | Markdown说明 | 流程说明、角色职责、分支解释 |

保存位置：{路径}
```

### 步骤 5.2 — 整理归纳问题

- **问题归纳**：
  - 本次 PM 反馈了哪些修改意见？归纳为哪几类问题？
  - 哪些问题是 PM 提供的信息不完整导致的（Agent 已主动追问）？
  - 哪些问题是 Agent 自身理解或结构设计有误导致的？
  - 哪些问题是 Mermaid 语法或 WPS 导入限制导致的？

- **经验总结**（归纳为可复用的规则）：
  - 本次积累的流程图设计经验（如某类流程的最佳组织方式）
  - Mermaid 语法在 WPS 中的实际表现（如哪些语法可用、哪些被忽略）
  - 需要补充到 `references/03-规则规范/流程图生成规范.md` 中的新规则

**输出格式**：
```
## 问题归纳与经验总结

### 问题归纳
| 问题分类 | 问题描述 | 原因分析 |
|---------|---------|---------|
| {分类} | {描述} | {原因} |

### 经验总结
1. {经验1}
2. {经验2}
3. ...
```

## 下一步操作引导机制

> **目的**：解决"AI 跳流程、未调用子Agent就推进"的问题。在每个关键节点完成后，输出标准化引导菜单请 PM 选择下一步。

### 输出格式模板

```
## [当前步骤名称] 已完成

### 执行情况
- {执行内容摘要}

### 下一步操作（请选择）
1. **[推荐] 进入下一阶段（{阶段名称}）**
2. 返回修改当前步骤
3. 其他操作（请说明）
```

### 5个关键节点引导表

| # | 节点位置 | 完成内容 | 引导选项 |
|---|---------|---------|---------|
| 1 | 阶段一完成 | 初始化确认 | 1.进入阶段二（背景了解）2.返回修改 3.其他 |
| 2 | 阶段二完成 | 背景了解确认 | 1.进入阶段三（需求梳理）2.返回修改 3.其他 |
| 3 | 阶段三完成 | 需求梳理确认，流程框架已确认 | 1.进入阶段四（流程图生成）2.返回修改 3.其他 |
| 4 | 阶段四完成 | 流程图生成+质量检查通过 | 1.进入阶段五（交付沉淀）2.调用流程图Agent重新生成 3.返回修改 4.其他 |
| 5 | 阶段五完成 | 交付产物+经验沉淀 | 1.任务结束 2.追加新的流程图 3.返回修改 4.其他 |
