> 从业务描述到Mermaid流程图的完整生成技能。支持泳道图/序列图/状态流转图等5种类型，输出.mmd+.md双格式，兼容WPS导入。

## 二、子Agent职能一览

| Agent | 角色定位 | 核心职能 | 触发时机 | 文件路径 |
|-------|---------|---------|---------|---------|
| 流程图Agent | 业务流程可视化工具 | 根据业务描述/PRD/场景描述输出逻辑闭环、角色分明的Mermaid流程图 | 阶段四步骤4.2 | `01-Agent定义/流程图Agent.md` |

### Agent核心能力

| 能力模块 | 说明 |
|---------|------|
| 上下文学习 | 自动读取项目已有上下文（PRD/功能清单/业务流程），自动判断项目类型 |
| 需求整理 | 将模糊零散输入整理成结构清晰的流程图框架，自动补全隐含角色和异常分支（标注`[AI补充]`） |
| 主动反问 | 5种必须反问：输入模糊/多种组织方式/关键角色缺失/分支条件不明/流程边界不明。每次不超过3个问题 |

### 硬约束（10条）

1. 多角色流程（≥2角色）必须用泳道图 2. 单角色流程用序列结构 3. 必须先确认结构再展开 4. 流程必须有明确起点和终点 5. 每个分支条件必须完整列出 6. 泳道间交互标注触发方/接收方/内容/等待机制 7. 不得遗漏超时处理路径 8. 不确定细节追问 9. 节点文字≤20字 10. 默认.mmd格式+.md备份

### 支持的流程图类型

| 类型 | 触发条件 | Mermaid实现 | 适用场景 |
|------|---------|------------|---------|
| 泳道图 | 流程涉及≥2角色（强制） | `graph TD`/`graph LR` + `subgraph` | 多角色业务流程、审批流 |
| 序列图 | 单角色操作流程 | `graph TD` 按时序展开 | 用户登录、单角色操作 |
| 状态流转图 | 对象状态变化 | `graph LR`/`graph TD` | 订单状态流转、状态管理 |
| 数据流转图 | 数据流动 | `graph LR` | 数据产生到消费路径 |
| 页面跳转图 | 页面导航逻辑 | `graph TD` | 页面跳转、前端路由 |

### WPS兼容性关键限制

- 支持：`graph TD`/`graph LR`、`subgraph`、节点定义、箭头
- 部分支持：`style`、节点内HTML标签
- 不支持：`classDef`/`class`、高级图表类型（gitgraph/journey）

## 六、快速决策树

> 主Agent根据PM需求，按此树快速路由。

```
PM需求
├─ "生成流程图""梳理流程" → 启动技能
│   ├─ 阶段一：确认保存位置
│   ├─ 阶段二：背景了解 + 行业规范检查
│   ├─ 阶段三：需求梳理
│   │   ├─ 步骤3.2：整理流程框架
│   │   │   └─ 流程图类型判断：
│   │   │       ├─ ≥2角色 → 泳道图（强制）
│   │   │       ├─ 单角色 → 序列图
│   │   │       ├─ 状态变化 → 状态流转图
│   │   │       ├─ 数据流动 → 数据流转图
│   │   │       └─ 页面导航 → 页面跳转图
│   │   └─ 步骤3.3：输出待确认问题清单
│   ├─ 阶段四：流程图生成
│   │   ├─ 步骤4.1：结构确认（强制）
│   │   │   └─ 加载：流程图模板.md（结构确认模板）
│   │   ├─ 步骤4.2：调用流程图Agent展开
│   │   │   └─ 加载：流程图Agent.md、流程图生成规范.md、流程图模板.md
│   │   └─ 步骤4.3：质量检查（6项自检）
│   └─ 阶段五：交付.mmd+.md + 经验沉淀
│
└─ 类型判断
    ├─ PM提到多个角色/部门 → 泳道图
    ├─ PM提到审批/审核流程 → 泳道图
    ├─ PM提到单个用户的操作 → 序列图
    ├─ PM提到状态/状态机 → 状态流转图
    ├─ PM提到数据流向 → 数据流转图
    └─ PM提到页面跳转 → 页面跳转图
```
