# 用户群体差异化设计指南

> **定位**：针对不同用户群体（低操作能力用户 vs 效率型用户 vs 普通消费者）提供差异化设计策略。
>
> **来源**：从P001-高速服务区物业项目的设计分化实践中提炼。
>
> **使用时机**：设计纲要阶段（阶段六步骤6.4），在设计基调确定时参考。

---

## 设计原则：用户差异决定设计方案

同一业务系统的不同端口/角色，因使用者能力不同，应采用不同的设计语言。

**核心洞察**：
- 用户群体的年龄、学历、使用频率决定了信息密度和交互复杂度
- 低操作能力用户需要"减少选择、放大目标、简化路径"
- 效率型用户需要"信息前置、快捷入口、批量操作"

---

## 用户群体分类与设计策略

| 用户类型 | 典型特征 | 核心诉求 | 设计策略 | 典型参数 |
|---------|---------|---------|---------|---------|
| **低操作能力用户** | 年龄35-55岁、学历偏低、操作频率高但每次单任务 | 快速完成、不出错、零学习成本 | 极简大字号、单路径、强引导 | 底部2-3Tab、字号16-22px、56px锚点比例、隐藏滚动条 |
| **效率型用户** | 高频使用、多任务并行、有管理经验 | 快速获取全局状态、高效处理 | 信息密度中等、快捷入口、数据看板 | 底部3-5Tab、字号12-18px、8px网格、信息层级清晰 |
| **普通消费者** | 偶尔使用、追求体验、容错性高 | 视觉吸引、交互流畅、反馈丰富 | 行业通用标准、情感化设计 | 视具体行业而定 |

## 低操作能力用户设计铁律

### 1. 首页即任务

打开APP直接看到"今天该做什么"，去除抽象统计数字。

**反面案例**：
- ❌ 首页展示"本月完成率85%"、"累计任务120个"等抽象数据
- ❌ 首页是功能导航入口，用户需要点击多次才能找到任务

**正面案例**：
- ✅ 首页直接展示"今日待巡检3项"，每项带状态标签
- ✅ 打开APP就是任务列表，无其他干扰信息

### 2. 一步完成

核心操作路径不超过2步。

**反面案例**：
- ❌ 完成任务需要：点击任务 → 进入详情 → 点击开始 → 完成巡检 → 拍照 → 填写备注 → 提交

**正面案例**：
- ✅ 完成任务：点击任务 → 直接展示操作按钮（拍照/确认完成）

### 3. 大字号

| 元素 | 字号 | 说明 |
|------|------|------|
| 首页标题 | ≥22px | 一眼可见当前状态 |
| 任务名称/导航 | ≥18px | 快速识别 |
| 正文内容 | ≥16px | 舒适阅读 |
| 辅助信息 | ≥14px | 最低可接受 |

### 4. 大触控区

| 元素 | 最小高度 | 说明 |
|------|---------|------|
| 底部Tab | 56px | 锚点比例系统 |
| 列表项 | 56-72px | 单/双行信息 |
| 按钮 | 48-56px | 主/次按钮 |
| 金刚区图标 | 40-48px | 底部文字12-13px |

### 5. 减少选择

- 避免复杂筛选、排序、配置
- 默认展示最常用的状态/数据
- 如需筛选，提供2-3个预设选项（今日/本周/本月）

### 6. 正向引导

- 空状态用**插图+文案+操作按钮**引导，不用抽象数字
- 用进度条/步骤指示器展示当前进度
- 用颜色区分状态（绿色=已完成、橙色=进行中、灰色=未开始）

## 效率型用户设计铁律

### 1. 数据看板先行

首页展示核心指标，3秒内获取全局状态。

**典型布局**：
```
├─ 数据概览区 [2x2或横向卡片，3-4个核心指标]
│   └─ 指标卡片：指标名 + 大数字 + 环比趋势
├─ 快捷入口 [金刚区，4-6个高频功能]
├─ 待办事项 [列表，高优先级置顶]
└─ 数据图表 [折线图/柱状图，支持时间维度切换]
```

### 2. 快捷入口密集

金刚区+工作台承载高频功能，减少层级跳转。

### 3. 信息层级清晰

| 层级 | 字号 | 字重 | 用途 |
|------|------|------|------|
| H1 | 20-24px | 600 | 页面标题 |
| H2 | 18px | 600 | 区块标题 |
| H3 | 16px | 500 | 列表标题/卡片标题 |
| Body | 14px | 400 | 正文内容 |
| Caption | 12px | 400 | 辅助信息/时间戳 |

### 4. 批量操作支持

- 列表支持多选（checkbox或长按）
- 顶部显示批量操作栏（通过/驳回/删除）
- 支持全选/反选

### 5. 状态筛选

- Tab切换快速筛选不同状态数据（全部/待处理/已处理）
- 支持时间维度筛选（今日/本周/本月/自定义）

## 设计分化决策树

```
同一个业务系统有多个端口/角色时：

├─ 确定各端口的目标用户群体
│   ├─ 低操作能力用户 → 应用"低操作能力用户设计铁律"
│   ├─ 效率型用户 → 应用"效率型用户设计铁律"
│   └─ 普通消费者 → 应用行业通用标准
│
├─ 对比各端口的设计参数差异
│   ├─ Tab数量：员工端2个 vs 管理端3-5个
│   ├─ 字号：员工端16-22px vs 管理端12-18px
│   ├─ 首页：任务列表 vs 数据看板
│   └─ 信息密度：低密度 vs 中高密度
│
└─ 在设计纲要中明确各端口的设计参数差异
    - 避免用一套设计参数覆盖所有端口
    - 每个端口独立输出设计参数
```

## 收录标准

满足以下条件的设计分化实践值得收录：
1. 同一业务系统中存在2+个不同用户群体的端口
2. 设计参数差异有明确的用户群体特征支撑
3. 差异化设计带来了可感知的使用体验提升
