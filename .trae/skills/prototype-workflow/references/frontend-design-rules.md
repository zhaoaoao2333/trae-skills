# Frontend Design Rules（案例驱动设计规则）

> **定位**：从具体页面/原型中提炼的、有案例依据的设计规则。
>
> **与 prototype-rules.md 的区别**：
> - `prototype-rules.md`：全行业通用规范（抽象、普适）
> - `frontend-design-rules.md`：案例驱动规则（具体、有案例依据）
>
> **来源**：
> - 设计分析师 Agent 从页面中提炼（`references/design-analyst.md`）
> - PM 手动补充的优秀设计规则
>
> **使用时机**：阶段六原型生成时，自动加载并遵守。

---

## 收录标准

只有满足以下全部条件的规则才能收录：

1. **可复用性**：适用于多个项目或多种场景，非一次性设计
2. **明确性**：规则描述具体、可执行，非主观感受
3. **案例支撑**：有至少1个实际案例作为依据
4. **非通用常识**：不是行业通用常识，而是具体做法

---

## 规则格式

每条规则必须按以下格式书写：

```markdown
【规则-分类-编号】规则名称
- 规则描述：（详细说明规则内容，具体到数值/行为/样式）
- 案例依据：（在哪个页面/原型中发现的，具体描述体现位置）
- 适用范围：（这条规则适合什么类型的产品/场景/行业）
- 关联规范：（与 prototype-rules.md 中哪条规则关联/补充）
```

**分类编号**：
- `N`：导航与信息架构（Navigation）
- `L`：布局与视觉层级（Layout）
- `I`：交互模式（Interaction）
- `S`：状态覆盖（State）
- `C`：组件规范（Component）

**编号规则**：按收录顺序递增，如 `【规则-N-001】`、`【规则-L-002】`

## 使用说明

### 阶段六加载规则

原型生成阶段（阶段六）自动加载本文件，规则优先级：

1. **frontend-design-rules.md 中的案例规则**（最高优先级，具体有依据）
2. prototype-rules.md 中的通用规范（次优先级，普适原则）
3. industry-templates.md 中的行业模板（参考结构）
4. component-library.md 中的组件实现（代码参考）

**冲突处理**：
- 如果案例规则与通用规范冲突 → 以案例规则为准（但需标注冲突，供后续审核）
- 如果两条案例规则冲突 → 标注【矛盾-需审核】，列出两条规则供PM判断

### 规则更新流程

```
页面/原型 → 设计分析师Agent提炼 → PM审核 → 追加到本文件 → 推送GitHub
```

- **独立**：frontend-design-rules 是全新规则，通用规范未覆盖
- **矛盾**：两条规则冲突，需审核
