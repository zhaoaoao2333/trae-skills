# 项目管理规则

## 项目资产

### 项目ID
- 格式：P + 三位数字（如 P001、P002）
- 由注册表分配，不重复不回收

### 文件夹命名
- 格式：P编号-项目简称-年月（如 P001-电商APP-2606）

### 标准子目录
```
P编号-项目简称-年月/
├── 00-项目记录/     ← 确认记录、断点续传、上下文记忆、版本记录
│   ├── context-memory.md   ← 上下文记忆文件
│   ├── version-log.md      ← 版本记录文件
│   └── *.md                ← 各阶段产出物历史版本
├── 01-需求文档/     ← PRD 文档
├── 04-原型/         ← 原型文件
└── 05-交付物/       ← 最终交付
```

### 项目注册表
- 位置：团队共享根目录
- 按状态分表管理

## 项目初始化

新项目必须先创建文件夹和标准子目录，按规范命名。

## 注册表管理

注册表为唯一真实来源，每次里程碑自动更新状态。

## 上下文管理

- 切换项目必须重置上下文
- 检测到异议主动提醒
- 每次确认写记录到 `00-项目记录/`，上下文断了可无缝恢复

## 上下文记忆管理

### 记忆文件维护

- **位置**：`00-项目记录/context-memory.md`
- **维护者**：AI 自动维护，PM 可查看
- **更新时机**：每个阶段结束时自动追加
- **读取时机**：每个阶段开始时自动读取

### 记忆内容规范

每条记忆记录包含：
- 日期时间
- 阶段名称
- 要点摘要（一句话）
- 详细内容（如有需要）
- 置信度标注（确定/推测/待验证）

### 遗忘检查

生成产出物前，AI 必须：
1. 读取记忆文件
2. 对照检查产出物是否包含所有已确认要点
3. 发现遗漏立即修正
4. 记录修正原因到记忆文件

## 版本回溯管理

### 版本记录维护

- **位置**：`00-项目记录/version-log.md`
- **维护者**：AI 自动维护
- **更新时机**：每次产出物保存时记录

### 版本命名规则

| 版本号变化 | 触发条件 |
|-----------|---------|
| 主版本 +1（v1.0 → v2.0） | 阶段切换时 |
| 次版本 +1（v1.0 → v1.1） | 同一阶段内重大修改 |

### 文件版本保存

- 每个阶段产出物保存为独立文件
- 文件名格式：`[内容]-v[版本号].md`
- 示例：`流程梳理-v1.0.md`、`PRD-v2.0.md`、`原型-v3.0.html`

### 回溯操作规范

1. PM 提出回溯请求（「回溯到 v1.2」）
2. AI 读取版本记录，定位目标版本
3. AI 加载目标版本的产出物
4. AI 确认回溯内容（展示关键差异）
5. PM 确认后，从目标版本继续工作
6. 新版本号接续（回溯到 v1.2 → 新版本 v1.3）
7. 记录回溯操作到版本日志

## 防幻觉规则

| 置信度 | 处理方式 |
|--------|---------|
| 确定 | 直接陈述 |
| 推测 | 标注「待验证」 |
| 未知 | 直接说不知道 |

禁止：
- 编造竞品功能
- 技术断言
- 行业数据
- 不存在的案例
