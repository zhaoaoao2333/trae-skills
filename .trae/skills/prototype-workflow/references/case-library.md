# 案例库沉淀机制

> 每次项目结束后，从原型设计中提取可复用的页面、组件、设计模式，沉淀到案例库。
>
> 案例库是**经验积累的核心载体**，让AI从"凭感觉设计"进化到"基于经验设计"。

---

## 一、沉淀时机

**触发条件**：项目进入阶段九（项目收尾）时，自动执行案例沉淀。

**沉淀流程**：
```
项目结束 → 质量评分回顾 → 筛选优秀设计 → 提取案例 → 分类归档 → 更新案例库
```

---

## 二、沉淀内容

### 1. 页面案例

**定义**：本次项目中设计优秀、可跨项目复用的完整页面。

**沉淀格式**：
```markdown
### 案例：[页面名称]
- **来源项目**：[项目ID]
- **行业类型**：[电商/社区/本地生活/工具...]
- **页面类型**：[首页/列表/详情/表单/个人中心...]
- **质量评分**：[XX分]
- **适用场景**：[什么类型的产品适合用这个页面]
- **设计亮点**：
  1. [亮点1，如：布局合理，视觉重心在上半屏]
  2. [亮点2，如：交互完整，包含中部弹窗+底部弹窗+Toast]
- **布局结构**：[ASCII图或文字描述]
- **复用建议**：[如何套用到新项目]
- **代码片段**：[关键HTML/CSS片段]
```

**示例**：
```markdown
### 案例：社区首页（金刚区+Feed流）
- **来源项目**：P001-羲盛智数社区服务
- **行业类型**：社区服务
- **页面类型**：首页
- **质量评分**：88分
- **适用场景**：有内容发布和社区互动的APP首页
- **设计亮点**：
  1. 金刚区8个入口覆盖核心功能，图标+文字清晰
  2. Feed流卡片信息分层合理（用户→内容→互动）
  3. 发布FAB突出，符合社区产品习惯
- **布局结构**：
  ```
  ├─ 顶部搜索+消息
  ├─ 金刚区 2×4
  ├─ Banner轮播
  ├─ 分类Tab
  └─ Feed流卡片
  ```
- **复用建议**：替换金刚区图标和Feed流内容即可适配新项目
```

### 2. 组件案例

**定义**：本次项目中创新的、可独立复用的组件。

**沉淀格式**：
```markdown
### 案例：[组件名称]
- **来源项目**：[项目ID]
- **组件类型**：[导航/列表/弹窗/状态/表单/按钮/其他]
- **创新点**：[与标准组件的区别，解决了什么问题]
- **适用场景**：[什么场景下使用这个组件]
- **代码片段**：[完整HTML/CSS/JS]
- **使用说明**：[如何引用、需要哪些CSS变量]
```

**示例**：
```markdown
### 案例：训练计划卡片（进度环+操作按钮）
- **来源项目**：P002-网球相机APP
- **组件类型**：列表项
- **创新点**：用圆形进度环展示训练完成度，直观且有成就感
- **适用场景**：需要展示进度/完成度的列表项
- **代码片段**：
  ```html
  <div class="plan-card">
    <div class="plan-progress">
      <svg class="progress-ring" viewBox="0 0 100 100">
        <circle class="progress-bg" cx="50" cy="50" r="45"/>
        <circle class="progress-fill" cx="50" cy="50" r="45" stroke-dasharray="283" stroke-dashoffset="70"/>
      </svg>
      <span class="progress-text">75%</span>
    </div>
    <div class="plan-info">...</div>
    <button class="plan-action">继续训练</button>
  </div>
  ```
```

### 3. 设计模式案例

**定义**：本次项目中解决特定设计问题的新模式。

**沉淀格式**：
```markdown
### 案例：[模式名称]
- **来源项目**：[项目ID]
- **解决的问题**：[具体设计问题]
- **解决方案**：[模式描述]
- **适用场景**：[什么类型的产品/页面适用]
- **与标准模式的区别**：[如果有类似模式，说明差异]
- **注意事项**：[使用时的注意点]
```

**示例**：
```markdown
### 案例：配置即时验证模式
- **来源项目**：P002-网球相机APP
- **解决的问题**：用户配置训练参数后，不知道效果是否符合预期
- **解决方案**：在配置详情页增加"测试"按钮，点击后弹出预览弹窗，实时展示配置效果
- **适用场景**：需要用户配置参数且效果可预览的工具类产品
- **与标准模式的区别**：标准模式是保存后查看，此模式是配置时即时预览
- **注意事项**：预览逻辑需要与真实逻辑一致，避免预览与实际效果不符
```

### 4. 避坑记录

**定义**：本次项目中踩过的坑，以及解决方案。

**沉淀格式**：
```markdown
### 避坑：[问题描述]
- **来源项目**：[项目ID]
- **问题现象**：[具体表现]
- **根本原因**：[为什么会发生]
- **解决方案**：[如何修复]
- **预防措施**：[以后如何避免]
- **相关规则**：[关联的规则编号]
```

**示例**：
```markdown
### 避坑：小程序胶囊按钮区放置内容
- **来源项目**：P001-羲盛智数社区服务
- **问题现象**：导航栏右上角放置了消息铃铛，与小程序胶囊按钮重叠
- **根本原因**：未考虑小程序端口的系统限制
- **解决方案**：消息入口移至底部导航「消息」Tab
- **预防措施**：设计时必须考虑端口特性，小程序顶部右侧禁止放置任何内容
- **相关规则**：布局规则-小程序适配、端口规范优先原则
```

## 三、优秀判定标准

### 判定维度

| 维度 | 标准 | 权重 |
|------|------|------|
| 质量评分 | ≥85分 | 30% |
| 零返工 | PM一次确认通过，无修改 | 25% |
| 复用价值 | 其他项目可直接套用 | 25% |
| 解决痛点 | 解决了之前项目的常见问题 | 10% |
| 创新度 | 有新的设计模式或交互方式 | 10% |

### 案例分级

| 级别 | 标准 | 使用方式 |
|------|------|---------|
| ⭐⭐⭐ 优秀案例 | 质量评分≥90，PM特别认可 | 新项目优先参照，生成设计纲要时主动推荐 |
| ⭐⭐ 良好案例 | 质量评分≥80，可复用 | 新项目参考，设计时查阅 |
| ⭐ 一般案例 | 质量评分<80，有参考价值 | 仅记录，不推荐直接使用 |

### 判定流程

```
项目结束
  ↓
回顾所有页面质量评分
  ↓
筛选评分≥80分的页面/组件
  ↓
评估复用价值和创新度
  ↓
分级（⭐⭐⭐/⭐⭐/⭐）
  ↓
按格式提取案例
  ↓
归档到案例库
```

## 四、案例库使用方式

### 生成设计纲要时

1. **确定行业类型** → 查阅对应行业的优秀案例
2. **确定页面类型** → 查找相似页面的案例
3. **参考案例布局** → 套用或调整
4. **标注案例来源** → 设计纲要中注明"参照案例：[案例名称]"

### 生成页面时

1. **遇到设计问题** → 查阅设计模式案例
2. **需要组件** → 查阅组件案例，直接复用代码
3. **不确定布局** → 查阅页面案例，参照结构

### 案例引用格式

```markdown
设计决策：
- 页面布局参照案例「社区首页（金刚区+Feed流）」(P001，⭐⭐⭐)
- 商品卡片使用组件库标准组件
- 空状态采用设计模式「引导模式」
```

## 五、案例库维护

### 定期清理

- 每季度回顾案例库
- 删除过时案例（APP改版导致布局失效）
- 更新案例分级（根据实际复用情况调整）

### 持续补充

- 每个项目结束后补充新案例
- 从头部APP更新中提炼新趋势
- 从用户反馈中提炼改进点
