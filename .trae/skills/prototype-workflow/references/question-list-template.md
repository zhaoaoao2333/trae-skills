# 待确认问题清单模板

> 用于AI整理业务流程后，输出需要PM与客户开会确认的问题清单。
>
> **目的**：把AI理解中的模糊点、矛盾点、遗漏点、待决策点暴露出来，让PM带着明确的问题去和客户开会，提高沟通效率。
>
> **输出时机**：阶段三步骤3.3，AI整理完业务流程后输出。

---

## 清单结构

### 问题编号规则

问题按 `Q-模块序号-问题序号` 编号，如 `Q-01-02` 表示模块1的第2个问题。

---

## 问题分类

| 类型 | 标识 | 说明 | 示例 |
|------|------|------|------|
| **模糊点** | [模糊] | 描述不清晰，有多种理解方式 | "快速处理"是指30分钟还是2小时？ |
| **矛盾点** | [矛盾] | 功能间逻辑冲突 | A规则说必须实名，B流程说游客可用 |
| **遗漏点** | [遗漏] | 缺少必要环节 | 退款流程中缺少"退款失败"的处理 |
| **待决策** | [决策] | 需要业务方决策的规则 | 优惠券能否叠加使用？ |
| **边界点** | [边界] | 边界条件不明确 | 商品库存为0时，已加入购物车的如何处理？ |

## AI识别问题的标准

### 必须列为问题的信号

1. **功能清单中出现以下词汇**：
   - "等"、"等等"、"其他"（范围不明确）
   - "快速"、"及时"、"合理"（标准不明确）
   - "视情况而定"、"酌情"（规则不明确）
   - "原则上"（有例外但不说明）

2. **业务流程缺失以下环节**：
   - 开始/结束条件
   - 异常处理分支
   - 权限判断节点
   - 数据校验规则

3. **跨功能逻辑冲突**：
   - 两个功能对同一数据的处理规则矛盾
   - 前置条件与后置结果不匹配
   - 角色权限与操作范围不符

4. **行业规范要求但未提及**：
   - 电商项目未提及售后/退款
   - 金融项目未提及风控/合规
   - 社交项目未提及内容审核

## PM开会确认后的处理

PM带着问题清单与客户开会后，向AI反馈会议结论：

**反馈格式**：
```
问题编号：Q-01-01
会议结论：[已确认 / 待进一步确认 / 客户也未确定]
确认内容：[具体结论]
需要调整的业务流程：[如有]

问题编号：Q-01-02
...
```

**AI处理原则**：
- **已确认**：按确认内容更新业务流程，标记为[已确认]
- **待进一步确认**：保留原问题，补充新发现的问题，输出《待确认问题清单V2》
- **客户也未确定**：标注[需PM决策]，给出2-3个方案供PM选择
