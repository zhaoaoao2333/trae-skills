# AI化可能性评估模板

> **评估颗粒度**：以独立的"用户故事"或"最小可交付的AI功能单元"为单位进行评估。一个项目可拆解为多个AI功能单元，每个单元单独评估。
>
> **目的**：培养PM的AI思考意识，在项目初期快速判断各功能单元是否适合引入AI解决。
>
> **时间控制**：每个功能单元15-20分钟，整项目不超过1小时。

---

## 使用流程

### 第一步：拆解AI功能单元

将项目涉及的业务流程拆解为独立的"用户故事"或"最小可交付的AI功能单元"。

**拆解原则**：
- 每个单元对应一个完整的"输入→处理→输出"闭环
- 单元之间尽量独立，减少耦合
- 颗粒度适中：既不过大（难以评估），也不过小（价值不明显）

**拆解示例**：

| 项目 | AI功能单元 | 说明 |
|------|-----------|------|
| 智能客服系统 | 单元1：用户意图识别 | 把用户问题分类到预定义意图 |
| | 单元2：智能回复生成 | 根据意图生成回复文案 |
| | 单元3：情绪识别 | 识别用户情绪状态，触发升级 |
| 商品推荐系统 | 单元1：用户画像构建 | 根据行为数据打标签 |
| | 单元2：推荐排序 | 根据画像排序商品 |

---

### 第二步：逐单元评估

对每个AI功能单元，依次完成以下7个维度的评估。

## 多单元汇总评估

当项目拆解为多个AI功能单元后，汇总各单元评估结果：

| 序号 | AI功能单元 | 适配性 | 综合建议 | 优先级 |
|------|-----------|--------|---------|--------|
| 1 | | | | |
| 2 | | | | |
| 3 | | | | |

**项目级AI策略**：
- **全部建议尝试**：项目整体适合AI化，按优先级逐个实施
- **部分建议尝试**：优先实施高适配性单元，低适配性单元寻找替代方案
- **全部不建议**：项目暂不适合AI化，按常规项目流程进行

---

## 输出要求

1. **每个功能单元**输出一份独立评估（单页）
2. **多单元项目**额外输出汇总评估表
3. 所有评估保存到 `00-项目记录/ai-assessment/`
4. 评估结果作为阶段三需求梳理的输入（高适配性单元融入AI功能设计）
