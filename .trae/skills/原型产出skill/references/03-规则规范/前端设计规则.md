# Frontend Design Rules（案例驱动设计规则）

> **定位**：从具体页面/原型中提炼的、有案例依据的设计规则。
>
> **与 prototype-rules.md 的区别**：
> - `prototype-rules.md`：全行业通用规范（抽象、普适）
> - `frontend-design-rules.md`：案例驱动规则（具体、有案例依据）
>
> **来源**：
> - 设计分析师 Agent 从页面中提炼（`references/01-Agent定义/设计分析师Agent.md`）
> - PM 手动补充的优秀设计规则
>
> **使用时机**：阶段六原型生成时，自动加载并遵守。

---

## 收录标准

只有满足以下全部条件的规则才能收录：

1. **可复用性**：适用于多个项目或多种场景，非一次性设计
2. **明确性**：规则描述具体、可执行，非主观感受
3. **案例支撑**：有至少1个实际案例作为依据
4. **非通用常识**：不是行业通用常识，而是具体做法

---

## 规则格式

每条规则必须按以下格式书写：

```markdown
【规则-分类-编号】规则名称
- 规则描述：（详细说明规则内容，具体到数值/行为/样式）
- 案例依据：（在哪个页面/原型中发现的，具体描述体现位置）
- 适用范围：（这条规则适合什么类型的产品/场景/行业）
- 关联规范：（与 prototype-rules.md 中哪条规则关联/补充）
```

**分类编号**：
- `N`：导航与信息架构（Navigation）
- `L`：布局与视觉层级（Layout）
- `I`：交互模式（Interaction）
- `S`：状态覆盖（State）
- `C`：组件规范（Component）

**编号规则**：按收录顺序递增，如 `【规则-N-001】`、`【规则-L-002】`

## 规则列表

> 以下为示例格式，实际规则由设计分析师Agent从页面中提炼后追加。

### 导航与信息架构（N）

【规则-N-001】示例规则：电商首页金刚区采用"4列2行"布局
- 规则描述：金刚区采用4列2行共8个入口的布局，每个入口包含40x40px图标+12px文字标签，图标选中态为品牌色填充，非选中态为灰色线框
- 案例依据：在电商类项目Pxxx首页中，金刚区采用此布局，用户点击率最高的4个功能放在第一行
- 适用范围：电商/本地生活/工具类App首页
- 关联规范：补充 prototype-rules.md 第九章"金刚区设计规则"

【规则-N-002】游戏App五Tab导航架构
- 规则描述：游戏类App底部导航推荐5个Tab：游戏/观战/社群/活动/更多，选中态使用品牌色+发光指示条
- 案例依据：在Jam3a项目P008中，5Tab架构覆盖游戏核心场景，品牌色选中态+顶部发光条增强识别
- 适用范围：综合游戏平台类App
- 关联规范：补充 prototype-rules.md 导航架构

---

### 布局与视觉层级（L）

【规则-L-001】暗色游戏页面视觉重心控制
- 规则描述：游戏类App暗色背景下，首屏视觉重心通过品牌色高亮区域（Banner/快速匹配按钮）引导，品牌色面积不超过首屏面积的15%
- 案例依据：在Jam3a项目P008游戏首页中，金色Banner+快速匹配按钮总面积约占首屏12%，用户视线自然聚焦
- 适用范围：游戏类App、深色主题产品
- 关联规范：补充 prototype-rules.md 视觉规则-01"品牌色仅用于主按钮、选中态、关键标签"

【规则-L-002】资产栏固定顶部模式
- 规则描述：有虚拟货币系统的App，顶部固定资产胶囊栏（52px高度），始终显示余额，点击跳转对应功能页
- 案例依据：在Jam3a项目P008中，所有一級页面顶部固定资产栏，用户随时可查看Gold/Diamond余额
- 适用范围：游戏类App、有虚拟货币的产品
- 关联规范：补充 prototype-rules.md 布局规则

---

### 交互模式（I）

【规则-I-001】游戏匹配等待交互
- 规则描述：匹配等待页使用脉冲圆环动画+预计等待时间+取消按钮，匹配成功后显示对手弹窗+VS动画（不超过3秒）
- 案例依据：在Jam3a项目P008匹配等待页中，脉冲雷达动画+15秒预计时间+取消按钮，匹配成功后对手信息弹窗+VS动画
- 适用范围：需要实时匹配的游戏类App
- 关联规范：补充 prototype-rules.md 交互规则

【规则-I-002】底部导航禁止滑动切换
- 规则描述：游戏类App底部导航Tab切换仅支持点击，不支持左右滑动切换，防止与游戏内手势冲突
- 案例依据：在Jam3a项目P008中，底部5个Tab仅点击切换，避免与Ludo等游戏内的滑动手势冲突
- 适用范围：游戏类App
- 关联规范：补充 prototype-rules.md 导航架构

### 组件规范（C）

【规则-C-001】段位徽章渐变色体系
- 规则描述：竞技类游戏的段位徽章使用固定渐变色体系（青铜→白银→黄金→铂金→钻石→大师），每级渐变色有明确色值
- 案例依据：在Jam3a项目P008中，6级段位徽章使用预定义渐变色，用户通过颜色即可识别段位等级
- 适用范围：有段位/等级体系的竞技游戏
- 关联规范：补充 prototype-rules.md 视觉规则

## 使用说明

### 阶段六加载规则

原型生成阶段（阶段六）自动加载本文件，规则优先级：

1. **frontend-design-rules.md 中的案例规则**（最高优先级，具体有依据）
2. prototype-rules.md 中的通用规范（次优先级，普适原则）
3. industry-templates.md 中的行业模板（参考结构）
4. component-library.md 中的组件实现（代码参考）

**冲突处理**：
- 如果案例规则与通用规范冲突 → 以案例规则为准（但需标注冲突，供后续审核）
- 如果两条案例规则冲突 → 标注【矛盾-需审核】，列出两条规则供PM判断

### 规则更新流程

```
页面/原型 → 设计分析师Agent提炼 → PM审核 → 追加到本文件 → 推送GitHub
```
