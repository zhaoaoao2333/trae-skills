## 一、电商行业

### 1.1 标准模块清单

| 必含模块（不询问直接加） | 常见模块（根据项目类型判断） | 可选模块（标注后加） |
|----------------------|------------------------|-------------------|
| 商品列表、商品详情、购物车、订单管理、收货地址、支付 | 优惠券、收藏、评价、物流追踪 | 积分商城、分销 |

### 1.2 通用业务规则（直接采用）

| 规则 | 默认值 |
|------|--------|
| 支付超时 | 30分钟未支付自动取消 |
| 退款流程 | 原路退回，3-7工作日 |
| 订单状态 | 待支付→已支付→已发货→已收货→已完成 |
| 评价机制 | 收货后可评，1-5星+文字 |
| 分页规则 | 每页20条 |
| 搜索规则 | 支持商品名+关键词搜索 |
| 通知推送 | 订单状态变更+促销 |
| 权限模型 | 用户+商家+平台 |

### 1.3 默认页面框架

**首页**：Banner(轮播) → 金刚区(8-10) → 活动区 → 推荐商品(双列)
**详情页**：图片轮播 → 价格+名称 → 规格选择 → 评价 → 详情

### 1.4 电商特定设计原则

#### 列表页默认展示商品而非中间商

**禁止**：团购列表页默认展示团长列表（用户视角是"找商品"不是"找团长"）
**正确**：
- 商品列表用双列网格展示商品
- 商品卡片下方展示团长头像+昵称
- 商品详情页有团长主页入口

#### 多供货商购物车分组

当存在多个供货商时：
- 购物车按供货商分组展示（分组卡片）
- 每个供货商分组独立结算
- 一次结算生成多个订单（按供货商拆分）
- 订单列表和详情显示供货商名称

## 八.5、游戏行业

### 8.5.1 标准模块清单

| 必含模块（不询问直接加） | 常见模块（根据项目类型判断） | 可选模块（标注后加） |
|----------------------|------------------------|-------------------|
| 游戏大厅、游戏对局、匹配系统、个人主页、好友系统、消息 | 战队/公会、排行榜、商城、充值、签到、活动中心 | 直播/观战、语聊房、通行证、装饰商店 |

### 8.5.2 通用业务规则

| 规则 | 默认值 |
|------|--------|
| 匹配超时 | 60秒未匹配成功提示扩大范围 |
| 断线重连 | 3分钟内可重连回局 |
| 货币体系 | 金币（免费获取）+ 钻石（付费获取） |
| 段位赛季 | 每赛季3个月，赛季末按段位发奖励 |
| 防沉迷 | 每日游戏时长限制（可选，根据市场法规） |
| 通知推送 | 对局开始/结束、好友邀请、赛事提醒 |
| 权限模型 | 玩家+管理员+审核员 |

### 8.5.3 默认页面框架

**首页（游戏大厅）**：顶部资产栏 → Banner轮播 → 游戏列表（金刚区） → 快速匹配 → 热门赛事
**游戏对局页**：全屏游戏画面 → 暂停菜单 → 结算页
**个人主页**：头像+段位 → 统计数据 → 游戏记录 → 装饰/成就

### 8.5.4 游戏特定设计原则

#### 色彩体系
- **主背景**：深色系优先（#0A0A1A、#121228），降低长时间游戏视觉疲劳
- **品牌色**：根据项目定位选择（如金色+紫色体现竞技荣誉感）
- **功能色**：成功绿/警告橙/错误红/信息蓝（全行业通用）

#### 交互规范
- **匹配等待**：实时显示匹配进度、预计等待时间、取消按钮
- **对局中**：禁止系统返回手势（防误触），提供"确认退出"二次确认
- **结算动画**：连胜特效、段位变化动画、奖励飞入效果
- **底部导航切换**：不支持滑动切换（防与游戏内手势冲突）

#### 组件特殊要求
- 游戏卡片需支持Hover上浮+发光效果
- 资产胶囊（金币/钻石余额）固定在顶部
- 段位徽章使用渐变色彩区分等级
- 匹配按钮需有脉冲动画吸引点击

### 8.5.5 性能要求

| 指标 | 标准 |
|------|------|
| 冷启动时间 | ≤ 3秒 |
| 页面切换 | ≤ 300ms |
| 游戏加载 | ≤ 5秒（首次）/ ≤ 2秒（缓存后） |
| 内存占用 | 前台≤ 500MB，后台≤ 100MB |
| 包体大小 | 初始下载≤ 100MB，资源按需下载 |

## 九、跨行业通用事件闭环

以下事件关系在所有行业中自动补全：

| 前置事件 | 自动触发 | 说明 |
|---------|---------|------|
| 用户注册 | → 自动登录 | 注册即登录 |
| 支付成功 | → 订单状态更新 → 推送通知 | 完成支付闭环 |
| 订单超时 | → 释放库存 → 退款 → 通知 | 超时回滚闭环 |
| 评价完成 | → 更新评分 → 通知商家 | 评价闭环 |
| 退款成功 | → 恢复库存 → 通知用户 | 退款闭环 |
| 登录/注册 | → 拉取用户信息 → 同步购物车/订单 | 初始化闭环 |
| 消息收到 | → 红点/角标更新 | 消息触达闭环 |
| 操作异常 | → 提示重试 → 记录日志 | 异常处理闭环 |

## 十、数据模型设计原则

### 10.1 同名不同义概念必须区分命名

**禁止**：同一项目中用"公告"同时指代"平台公告"和"主页公告"
**正确**：
- 平台公告（平台→团长/用户）
- 主页公告（团长→居民）
- 系统通知（系统→用户）

**命名规范**：当发现同一词汇在不同场景有不同含义时，必须加前缀区分。

### 10.2 角色权限边界检查清单

设计页面时，必须检查：
- [ ] 当前角色是否有权限执行此操作？
- [ ] 此操作是否应由其他角色/系统执行？
- [ ] 页面是否包含当前角色不该看到的敏感信息？
- [ ] 操作按钮是否超出了当前角色的职责范围？

**示例**：团长端订单详情页不应有"标记发货"按钮（发货由供货商PC端操作）
