# 设计模式库

> 常见设计问题的解决方案，AI遇到类似问题时直接套用。
>
> 每个模式包含：**问题描述 → 解决方案 → 适用场景 → 示例代码 → 注意事项**。

---

## 模式1：分区模式

**问题**：首页信息太多，如何组织？

**解决方案**：按功能分区，从上到下依次排列：Banner→金刚区→横向滚动→纵向列表。

**适用场景**：电商首页、本地生活首页、内容平台首页。

**示例**：
```
首页分区：
├─ 顶部搜索区 [核心操作]
├─ 金刚区 [功能入口]
├─ Banner轮播 [运营位]
├─ 限时秒杀 [横向滚动，促活]
├─ 分类Tab [筛选]
└─ 商品推荐 [纵向列表，核心内容]
```

**注意事项**：
- 每个分区用留白（16-24px）区分
- 视觉重心在上半屏
- 不同分区使用不同布局方式（网格/横滑/纵向）

## 模式2：信息分层模式

**问题**：列表项信息复杂，如何排布？

**解决方案**：按信息优先级分层排列：标题→描述→标签→价格→操作。

**适用场景**：商品列表、门店列表、订单列表、帖子列表。

**示例**：
```
列表项信息层级：
第一层（最重要）：标题 [16px Bold，最多2行]
第二层（次要）：描述/地址/时间 [14px 灰色]
第三层（辅助）：标签 [10px 品牌色背景]
第四层（操作）：价格+按钮 [14px 红色+44px按钮]
```

**注意事项**：
- 每层信息用间距或字号区分
- 操作按钮放在最右侧或底部
- 超过4层信息考虑精简或折叠

## 模式3：主次分离模式

**问题**：操作按钮太多，界面混乱？

**解决方案**：主操作外露，次操作收敛到更多菜单或ActionSheet。

**适用场景**：详情页、列表项、个人中心。

**示例**：
```
商品详情页操作：
主操作（外露）：加入购物车、立即购买 [底部固定栏]
次操作（图标按钮）：收藏、客服、分享 [底部栏左侧]
更多操作（ActionSheet）：举报、投诉、复制链接 [点击更多]
```

**注意事项**：
- 主操作不超过2个
- 次操作3-5个用图标按钮
- 更多操作超过3个用ActionSheet

---

## 模式4：分步模式

**问题**：表单太长，用户填写压力大？

**解决方案**：将长表单拆分为多步骤，每步聚焦一个主题。

**适用场景**：注册流程、下单流程、发布流程、设置流程。

**示例**：
```
下单流程分步：
步骤1：确认商品 [商品信息+规格确认]
步骤2：填写地址 [收货人+手机号+地址]
步骤3：选择支付 [支付方式]
步骤4：确认订单 [订单汇总+提交]
```

**注意事项**：
- 每步不超过5个输入项
- 显示进度指示（步骤条）
- 允许返回上一步修改
- 最后一步提供完整信息确认

## 模式5：引导模式

**问题**：无数据时，页面空白，用户困惑？

**解决方案**：插图+引导文案+操作按钮，引导用户完成首次操作。

**适用场景**：空状态页面、新用户首次进入、功能未启用。

**示例**：
```
购物车空状态：
┌──────────────────┐
│     [购物车插图]  │
│   购物车还是空的   │
│  去逛逛，发现好物  │
│   [  去逛逛  ]    │
└──────────────────┘
```

**注意事项**：
- 插图风格与产品一致
- 文案不超过两行
- 按钮文案用动词开头（"去添加"而非"添加"）
- 按钮跳转目标明确

## 模式6：筛选抽屉模式

**问题**：列表内容多，用户需要快速筛选？

**解决方案**：顶部筛选栏+底部弹窗，支持多条件组合筛选。

**适用场景**：商品列表、门店列表、订单列表、搜索结果。

**示例**：
```
筛选交互：
1. 用户点击"筛选"按钮
2. 底部弹出筛选抽屉
3. 抽屉内：分类选择+价格区间+排序方式
4. 用户选择后点击"确定"
5. 列表刷新，显示筛选结果
6. 顶部显示已选筛选条件标签（可删除）
```

**注意事项**：
- 常用筛选条件放顶部快捷栏
- 复杂筛选放底部抽屉
- 已选条件可一键清除
- 筛选结果为空时展示引导

## 模式7：规格弹窗模式

**问题**：商品有多规格，用户如何选择？

**解决方案**：底部弹窗展示规格矩阵，选择后实时更新价格和库存。

**适用场景**：电商商品详情、团购套餐选择、服务预约。

**示例**：
```
规格选择弹窗：
┌──────────────────┐
│  [商品缩略图]     │
│  价格：¥99       │
│  已选：红色/L    │
├──────────────────┤
│ 颜色：○红 ●蓝 ○黑│
│ 尺码：○S ●M ○L  │
├──────────────────┤
│ 库存：剩余23件   │
├──────────────────┤
│    [  确定  ]    │
└──────────────────┘
```

**注意事项**：
- 缺货规格置灰不可选
- 选择后实时更新价格
- 未选全规格时确定按钮禁用
- 显示库存提示（紧张时标红）

## 模式8：左滑操作模式

**问题**：列表项需要快捷操作，但空间有限？

**解决方案**：列表项左滑露出操作按钮（删除/收藏/置顶）。

**适用场景**：消息列表、收藏列表、订单列表、文件列表。

**示例**：
```
左滑操作：
正常态：[头像][标题][时间]
左滑后：[头像][标题][时间] [收藏][删除]
```

**注意事项**：
- 左滑距离不超过屏幕宽度的40%
- 操作按钮不超过3个
- 危险操作（删除）放最右侧，红色背景
- 点击其他区域自动收起

---

## 模式9：二次确认模式

**问题**：重要操作（删除/取消/支付）容易误触？

**解决方案**：点击后弹出确认弹窗，用户确认后才执行。

**适用场景**：删除订单、取消预约、退出登录、清空数据。

**示例**：
```
二次确认弹窗：
┌──────────────────┐
│    确认删除？     │
│  删除后不可恢复   │
│ [取消]  [删除]   │
└──────────────────┘
```

**注意事项**：
- 弹窗标题明确操作内容
- 说明操作后果（不可逆操作必须提示）
- 取消按钮在左，确认按钮在右
- 危险操作按钮用红色

---

## 模式10：骨架屏模式

**问题**：数据加载时白屏，用户以为卡死？

**解决方案**：用灰色占位块模拟内容形状，加载完成后渐显真实内容。

**适用场景**：列表页、详情页、首页、任何有数据加载的页面。

**示例**：
```
骨架屏：
加载前：[灰色块][灰色条][灰色条]
加载后：[真实图片][真实标题][真实价格]
```

**注意事项**：
- 骨架屏形状与真实内容一致
- 使用动画（ shimmer 效果）提示加载中
- 加载超时（10s）显示重试入口
- 优先用于首屏内容

## 模式使用说明

### 选择模式的方法

1. **识别设计问题**（信息太多/操作太多/表单太长/无数据...）
2. **查阅模式库**，找到匹配的模式
3. **套用模式结构**，替换为业务内容
4. **根据场景调整**（增删步骤、调整优先级）

### 模式组合使用

多个模式可以组合：
- 首页 = 分区模式 + 信息分层模式
- 商品详情 = 主次分离模式 + 规格弹窗模式 + 二次确认模式
- 列表页 = 信息分层模式 + 筛选抽屉模式 + 左滑操作模式 + 骨架屏模式

## 模式11：暗色品牌色模式（游戏专用）

**问题**：游戏类App需要营造竞技氛围，同时保证长时间使用不疲劳？

**解决方案**：深色背景为底，品牌色（金色/紫色）用于关键交互和选中态，发光效果克制使用。

**适用场景**：竞技游戏、游戏平台、电竞App。

**示例**：
```
色彩层级：
├─ 最底层：#0a0a0f（页面背景）
├─ 卡片层：#1a1a24（比背景亮一级）
├─ 输入层：#12121a（比卡片暗一级）
├─ 品牌色：仅用于主按钮、选中态、关键标签
└─ 发光效果：仅用于选中态、CTA按钮、稀有奖励
```

**注意事项**：
- 品牌色不做大面积背景色
- 发光效果不滥用，避免光污染
- 文字使用纯白色保证对比度

## 模式12：资产胶囊固定模式（游戏专用）

**问题**：游戏App中金币/钻石余额需要随时可见？

**解决方案**：在页面顶部固定资产胶囊栏，始终显示当前余额。

**适用场景**：有虚拟货币系统的游戏App。

**示例**：
```
顶部资产栏：
├─ 头像（点击→个人主页）
├─ 🪙 12,500（点击→充值中心）
├─ 💎 350（点击→商城）
└─ 🔔 通知（红点角标）
```

**注意事项**：
- 资产胶囊仅在一級页面显示
- 点击胶囊跳转对应功能页
- 余额变化需有数字滚动动画

## 模式13：匹配等待模式（游戏专用）

**问题**：游戏匹配需要等待，如何减少用户焦虑？

**解决方案**：匹配等待页显示脉冲动画+预计等待时间+取消按钮，匹配成功后显示对手信息弹窗。

**适用场景**：所有需要实时匹配的游戏。

**示例**：
```
匹配等待页：
├─ 脉冲圆环动画（雷达搜索效果）
├─ "匹配中..." 文字
├─ "预计等待 15s" 倒计时
├─ 取消按钮（幽灵按钮）
└─ 匹配成功 → 对手信息弹窗 + VS动画
```

**注意事项**：
- 匹配时间超过30秒需提示扩大搜索范围
- 取消匹配需即时响应
- 匹配成功后的动画不超过3秒

## 模式14：双形式原型模式（全行业通用）

**问题**：一份原型既要满足开发全局浏览，又要满足用户测试体验？

**解决方案**：生成平铺版（所有页面同时展示）和手机版（单页交互模拟）两种形式。

**适用场景**：所有需要原型交付的项目。

**示例**：
```
平铺版（V3.1）：
├─ 所有页面375×812并排展示
├─ 页面目录侧边栏导航
├─ 适合需求评审和开发阅读

手机版（V3.2）：
├─ 单页面全屏显示
├─ 完整页面跳转和返回
├─ 适合交互演示和用户测试
```

**注意事项**：
- 平铺版强制所有页面`display:flex !important`
- 手机版默认`display:none`，仅激活页`display:flex`
- 两种版本的HTML内容相同，仅CSS和JS不同

## 模式15：父级映射返回模式（全行业通用）

**问题**：复杂原型（>15页）中，history栈返回逻辑容易出错（栈空报错、连续点击跳页、多入口返回非预期）？

**解决方案**：使用pageParent对象定义每个页面的明确父级，goBack()直接跳转父级页面。

**适用场景**：页面数>15页的复杂原型、多入口页面（同一页面可从多处进入）。

**示例**：
```javascript
const pageParent = {
  'game-detail': 'game-hall',
  'matching': 'game-detail',
  'game-result': 'matching',
  'profile': 'game-hall',
  'settings': 'profile',
  'game-hall': null,
};

function goBack(currentPageId) {
  const parent = pageParent[currentPageId];
  if (parent) {
    showPage(parent);
  } else {
    showPage('game-hall');
  }
}
```

**注意事项**：
- 一级页面父级设为null，返回时停留在当前页或回首页
- 多入口页面定义固定父级（选择最符合用户心智的主入口）
- 不要与history栈模式混用

## 模式16：分批生成模式（全行业通用）

**问题**：原型页面数量多（>20页），单次生成复杂度高、容易出错、问题定位困难？

**解决方案**：按优先级分批生成，每批独立生成和质检，最终组装为单HTML文件。

**适用场景**：页面数>20页的中大型原型项目。

**示例**：
```
生成流程：
├─ 第1批：P0核心页面（16页）
│   ├─ 独立脚本生成页面HTML
│   ├─ 即时质检（页面数/色彩/字体/交互）
│   └─ PM确认核心路径无问题
├─ 第2批：P1配套页面（18页）
│   ├─ 独立脚本生成页面HTML
│   ├─ 即时质检
│   └─ PM确认配套功能完整
└─ 组装阶段
    ├─ assemble脚本合并为单HTML文件
    ├─ 全链路校验（跳转/返回/交互闭环）
    └─ PM终审
```

**注意事项**：
- P0批次完成后需PM确认再生成P1
- 每批使用独立脚本，降低单次复杂度
- 组装时需处理CSS变量统一、JS函数合并、页面ID去重

## 模式17：自动化质检模式（全行业通用）

**问题**：原型生成后人工质检耗时且容易遗漏（色彩违规、字体违规、页面数量不符、语言切换覆盖率不足）？

**解决方案**：编写自动化质检脚本，对生成的HTML文件进行静态分析，输出质检报告。

**适用场景**：所有原型项目，特别是页面数>15页的中大型原型。

**示例**：
```javascript
// 质检脚本核心检查项
const checks = {
  // 1. 色彩违规检查
  colorViolations: () => {
    const allowedColors = ['#F7F7F7', '#333', '#666', '#999', '#CCC', '#D03030'];
    // 扫描所有CSS颜色值，找出不在允许列表中的色值
    // 排除游戏功能色（如棋盘四色）
  },
  // 2. 字体违规检查
  fontViolations: () => {
    // 检查是否使用了Google Fonts等外部字体引用
    // 仅允许系统字体（-apple-system, sans-serif等）
  },
  // 3. 页面数量检查
  pageCount: () => {
    // 统计HTML中page容器的数量，与PRD要求对比
  },
  // 4. 语言切换覆盖率检查
  langSwitchCoverage: () => {
    // 统计class="t"的元素数量，检查是否有遗漏的文本节点
  },
  // 5. 平铺版显示检查
  flatDisplay: () => {
    // 检查平铺版所有页面是否display:flex
    // 检查页面标签是否为中文
  },
};

// 输出质检报告
function runQualityCheck(htmlFilePath) {
  const results = Object.entries(checks).map(([name, fn]) => ({
    check: name,
    passed: fn().length === 0,
    issues: fn(),
  }));
  return results;
}
```

**注意事项**：
- 质检脚本应在原型生成后立即运行，不等验收员介入
- 色彩检查需排除游戏功能色等合理例外
- 平铺版标签检测需使用正确的正则匹配（中文字符范围）
- 质检报告作为验收员测试的辅助输入，不替代用户视角测试

> **案例依据**：Jam3a项目P008中编写自动化质检脚本检查色彩违规、字体违规、页面数量、语言切换等，有效提高质检效率。V5质检通过0色彩违规、0字体违规。
