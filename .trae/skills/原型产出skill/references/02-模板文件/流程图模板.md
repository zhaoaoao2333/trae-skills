# 流程图模板

> 本文件提供流程图输出的标准格式和各场景模板骨架。
> 遵循 `references/流程图生成规范.md` 中的规则。

---

## 一、结构确认模板

输出完整流程图前，必须先输出以下结构确认内容：

```
【流程名称】：XXX

【流程类型】：多角色泳道图 / 单角色序列图 / 状态流转图

【涉及角色】：
- 角色1：XXX（说明角色在流程中的职责）
- 角色2：XXX
- 角色3：XXX（如有）

【流程路径概览】：
- 正向路径：角色→步骤→步骤→...→完成
- 主要分支：[条件A→处理A]、[条件B→处理B]
- 异常路径：[超时→处理]、[失败→处理]、[权限不足→处理]

【流程起点】：XXX
【流程终点】：XXX

以上结构是否准确？确认后我将展开完整流程图。有调整请告诉我。
```

## 二、Mermaid 输出格式

### 格式规则

- 使用 `graph TD`（从上到下）或 `graph LR`（从左到右）
- 节点 ID 用有意义的缩写：`U` 用户、`S` 系统、`M` 商家、`D` 判断、`E` 异常
- 节点文字用方括号 `[]`、判断用花括号 `{}`、起止用双圆括号 `(())`
- 正常流程用实线箭头 `-->`
- 跨角色通知/回调用虚线箭头 `-.->`
- 分支条件标注在箭头上：`-- 条件 -->`
- 文件头部用 `%%` 注释标注流程元信息

### 完整格式示例（多角色泳道图）

```mermaid
graph TD
    %% 流程名称：用户下单支付流程
    %% 流程类型：多角色泳道图
    %% 涉及角色：用户、系统、商家

    subgraph 用户
        U1([开始]) --> U2[浏览商品]
        U2 --> U3[选择规格]
        U3 --> U4[提交订单]
        U4 --> U10[选择支付方式]
        U10 --> U11[完成支付]
        U11 --> U12[查看订单状态]
        U12 --> U13([订单完成])
    end

    subgraph 系统
        S1[展示商品详情] --> S2{校验库存}
        S2 -- 库存充足 --> S3[锁定库存]
        S2 -- 库存不足 --> S4[返回库存不足]
        S3 --> S5[生成订单]
        S5 --> S6[调用支付接口]
        S6 --> S7{支付结果}
        S7 -- 成功 --> S8[更新订单状态]
        S7 -- 失败 --> S9[释放库存]
        S7 -- 超时 --> S10[自动取消订单]
        S8 --> S11[通知商家]
        S10 --> S12[释放库存]
    end

    subgraph 商家
        M1[接收订单通知] --> M2[确认订单]
        M2 --> M3[准备发货]
        M3 --> M4[填写物流]
        M4 --> M5[发货]
    end

    U4 -.->|提交| S2
    S4 -.->|提示| U2
    S5 -.->|订单生成| U10
    S11 -.->|新订单| M1
    M5 -.->|物流信息| S8
    S8 -.->|状态更新| U12
    S9 -.->|支付失败| U13
    S12 -.->|已取消| U13
```

### 完整格式示例（单角色序列图）

```mermaid
graph TD
    %% 流程名称：用户登录流程
    %% 流程类型：单角色序列图
    %% 涉及角色：用户、系统

    A([开始]) --> B[打开登录页]
    B --> C[输入手机号]
    C --> D{格式正确?}
    D -- 是 --> E[获取验证码]
    D -- 否 --> F[提示格式错误]
    F --> C
    E --> G[输入验证码]
    G --> H{校验结果}
    H -- 正确 --> I[登录成功]
    H -- 错误 --> J[提示错误]
    J --> K{错误次数<5?}
    K -- 是 --> G
    K -- 否 --> L[锁定15分钟]
    L --> M([结束])
    I --> N[跳转首页]
    N --> M
```

### 完整格式示例（状态流转图）

```mermaid
graph LR
    %% 流程名称：订单状态流转图
    %% 流程类型：状态流转图
    %% 涉及对象：订单

    A[待付款] -- 支付成功 --> B[待发货]
    A -- 超时15分钟 --> C[已取消]
    A -- 用户取消 --> C
    B -- 商家发货 --> D[待收货]
    B -- 商家取消 --> C
    D -- 用户确认收货 --> E[已完成]
    D -- 超时7天自动确认 --> E
    D -- 申请退款 --> F[退款中]
    F -- 商家同意 --> C
    F -- 商家拒绝 --> D
    E -- 申请售后 --> G[售后中]
```

## 三、场景模板骨架

### 3.1 多角色业务流程（泳道图）

```mermaid
graph TD
    subgraph 角色A
        A1[步骤1] --> A2[步骤2]
        A2 --> A3[步骤3]
    end

    subgraph 角色B
        B1[步骤1] --> B2[步骤2]
        B2 --> B3{判断条件}
        B3 -- 条件1 --> B4[结果1]
        B3 -- 条件2 --> B5[结果2]
    end

    subgraph 角色C
        C1[步骤1] --> C2[步骤2]
    end

    A2 -.->|通知| B1
    B4 -.->|回调| A3
    B5 -.->|通知| C1
    C2 -.->|完成| A3
```

### 3.2 审批流（泳道图）

```mermaid
graph TD
    subgraph 申请人
        A1[提交申请] --> A2[查看审批进度]
        A2 --> A3([结束])
    end

    subgraph 审批人
        B1{审批判断}
        B1 -- 通过 --> B2[审批通过]
        B1 -- 驳回 --> B3[审批驳回]
        B1 -- 转交 --> B4[转交他人]
        B4 --> B1
    end

    subgraph 系统
        S1[发送审批通知]
        S2[记录审批结果]
        S3[发送结果通知]
    end

    A1 -.->|提交| S1
    S1 -.->|通知| B1
    B2 -.->|通过| S2
    B3 -.->|驳回| S2
    S2 -.->|结果| S3
    S3 -.->|通知| A2
```

### 3.3 单角色操作流程（序列图）

```mermaid
graph TD
    A([开始]) --> B[步骤1]
    B --> C[步骤2]
    C --> D{判断条件}
    D -- 条件1 --> E[处理1]
    D -- 条件2 --> F[处理2]
    E --> G[步骤3]
    F --> G
    G --> H([结束])
```

### 3.4 状态流转图

```mermaid
graph LR
    A[状态A] -- 触发条件1 --> B[状态B]
    A -- 触发条件2 --> C[状态C]
    B -- 触发条件3 --> D[状态D]
    C -- 触发条件4 --> D
    D -- 触发条件5 --> E[状态E]
```

### 3.5 页面跳转流

```mermaid
graph TD
    A[首页] -- 点击入口1 --> B[页面1]
    A -- 点击入口2 --> C[页面2]
    B -- 点击按钮 --> D[页面3]
    C -- 点击返回 --> A
    D -- 提交成功 --> E[结果页]
    D -- 提交失败 --> F[错误页]
    F -- 点击重试 --> D
```

### 3.6 数据流转图

```mermaid
graph LR
    A[数据源A] --> B[数据处理]
    C[数据源B] --> B
    B --> D{数据校验}
    D -- 校验通过 --> E[数据存储]
    D -- 校验失败 --> F[错误处理]
    E --> G[数据消费端]
```

## 四、Markdown 说明文件模板

```markdown
# 【流程名称】

## 流程概述
- 流程类型：多角色泳道图 / 单角色序列图 / 状态流转图
- 涉及角色：角色1、角色2、角色3
- 流程起点：XXX
- 流程终点：XXX

## 角色职责
- **角色1**：职责描述
- **角色2**：职责描述
- **角色3**：职责描述

## 分支说明
- 分支条件1 → 处理结果1
- 分支条件2 → 处理结果2
- 分支条件3 → 处理结果3

## 异常处理
- 异常类型1：处理方式
- 异常类型2：处理方式
- 异常类型3：处理方式

## 备注
- AI 补充节点 X 个
- 待确认节点 X 个
```

## 五、WPS 导入快速检查单

导入 WPS 前，确认以下事项：

- [ ] 使用 `graph TD` 或 `graph LR`，非其他图表类型
- [ ] 节点定义使用 `[]` `{}` `(())`，无复杂形状
- [ ] 箭头使用 `-->` `-.->` `-- 文字 -->`，无粗箭头
- [ ] 未使用 `classDef` / `class` 语法
- [ ] 未使用 `style` 语法（或仅在 HTML 预览中使用）
- [ ] 无语法错误（可在 Mermaid Live Editor 验证）
- [ ] 文件编码为 UTF-8
