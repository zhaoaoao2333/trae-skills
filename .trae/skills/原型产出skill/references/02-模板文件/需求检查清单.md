# 需求梳理检查清单

## 业务流程梳理检查清单（阶段三）

### 端口确认
- [ ] 确认需要覆盖的端口（iOS/Android/Web/小程序）
- [ ] 每个端口的设计规范已明确

### 角色确认
- [ ] 列出所有系统角色
- [ ] 每个角色的核心诉求已明确
- [ ] 角色间的交互关系已明确

### 主流程
- [ ] 核心业务流程已步骤化描述
- [ ] 每个步骤的输入/输出已明确
- [ ] 流程无断点（每步都有明确的下一步）
- [ ] 流程无矛盾（无前后冲突的描述）

### 取消路径
- [ ] 用户中途取消的路径已确认
- [ ] 取消后的状态回滚已确认

### 异常路径
- [ ] 网络异常处理已确认
- [ ] 超时处理已确认
- [ ] 数据异常处理已确认
- [ ] 权限不足处理已确认

### 行业规范复核
- [ ] 对照行业规范，检查是否有遗漏的必要模块
- [ ] 遗漏项已询问 PM（标注 [已排除] 或补充到方案）
- [ ] 流程梳理结果符合行业标准和合规要求

---

## 功能模块细化检查清单（阶段四）

### 模块拆分
- [ ] 所有功能模块已列出
- [ ] 每个模块优先级已标注（高优/中优/低优）
- [ ] 模块间关联关系已明确

### 每个模块的细化
对每个模块逐一检查：
- [ ] 业务规则（校验规则、约束条件）
- [ ] 数据逻辑（来源、计算、存储）
- [ ] 权限控制（谁可操作、权限边界）
- [ ] 关联关系（依赖、交互）
- [ ] 异常处理（出错应对策略）
- [ ] 边界条件（最大值、最小值、空值）

### 标注
- [ ] MVP 项已标注 [MVP]
- [ ] 不确定项已标注 [待PM确认]
- [ ] 推测项已标注「待验证」

### 整体检查
- [ ] 模块间无功能遗漏
- [ ] 模块间无功能重复
- [ ] 所有模块的优先级合理

### 行业规范复核
- [ ] 对照行业规范，检查功能模块是否有遗漏（如：设置、帮助中心、关于我们等）
- [ ] 遗漏项已询问 PM（标注 [已排除] 或补充到方案）
- [ ] 每个模块的规则符合行业标准和合规要求
- [ ] 输出格式已与 PM 确认
