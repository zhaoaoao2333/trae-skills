# 会议纪要整理规范

> 本文件定义会议纪要整理的全部规则。会议纪要整理Agent和所有涉及纪要输出的场景必须遵守本规范。
> 具体输出格式参见 `references/02-模板文件/会议纪要模板.md`。

---

## 一、核心原则

1. **提炼而非复述**：不逐字记录，提炼核心观点、决策和行动项。
2. **决策导向**：每个议题必须有明确结论，未形成结论的标注 `[待决策]`。
3. **行动明确**：每个待办必须有责任人、截止时间和可执行的具体动作。
4. **结构清晰**：按议题组织，不按时间流水账，同议题内容合并。
5. **如实记录**：保留关键分歧点，不强行统一为"一致通过"。

---

## 二、纪要结构规范

### 必含模块

| 模块 | 说明 |
|------|------|
| 基本信息 | 会议时间、地点、参会人员、主持人、记录人 |
| 会议目的 | 一句话说明会议要解决什么问题 |
| 核心结论 | 3-5条本次会议最重要的结论，放在最前面 |

### 选含模块（根据会议类型选择）

| 模块 | 说明 |
|------|------|
| 议题讨论 | 每个议题的讨论要点和结论。小会可省略，直接放入核心结论 |
| 待办事项 | 责任人、截止时间、状态 |
| 下次会议 | 时间、议题、参会人员 |
| 附录 | 参考资料、会议白板照片、相关文档链接 |

---

## 三、基本信息规范

### 必填字段

| 字段 | 格式要求 |
|------|---------|
| 会议时间 | YYYY年MM月DD日 HH:MM-HH:MM |
| 会议地点 | 线下写具体位置，线上写"线上-腾讯会议/飞书会议" |
| 参会人员 | 姓名（角色或部门），多人用顿号分隔 |
| 记录人 | 整理这份纪要的人 |

### 选填字段

主持人、请假人员、旁听人员

---

## 四、核心结论规范

- 放在纪要最前面，让读者30秒内了解会议成果
- 3-5条，每条控制在30字以内
- 结论是"**决定了什么**"，不是"讨论了什么"
- 多条结论用编号排列，按重要性排序
- 未形成结论的事项不在核心结论中出现

### 正确 vs 错误示例

| 正确 ✅ | 错误 ❌ |
|---------|---------|
| 确定V2.1版本包含5个功能模块 | 讨论了V2.1版本的功能范围 |
| 消息推送功能延至V2.2版本 | 关于消息推送功能进行了充分讨论 |
| 设计稿7月16日前完成终稿 | 设计资源协调问题已沟通 |

---

## 五、议题讨论规范

### 议题命名

- 格式："议题X：主题"
- 主题要反映讨论内容，不能只写"议题一""议题二"
- 示例："议题一：V2.1版本需求清单评审"

### 讨论内容记录

- 提炼各发言人核心观点，标注发言人身份
- 不记录逐字稿，不记录跑题内容
- 首次出现的人名后用括号标注角色或部门
- 多个方案时保留各自优缺点简述

### 结论记录

- 用 **"结论："** 加粗标注
- 当场未形成结论的标注 **"[待决策]"** 并说明原因
- 结论有前提条件的必须标注前提

### 口语转书面示例

| 原始表述 | 书面表述 |
|---------|---------|
| "王五说这个做不了，太难了" | 王五评估开发量较大，建议延期 |
| "那个优惠券我觉得应该提前" | 李四建议将优惠券功能优先级提升 |
| "这个先放一放吧" | 该事项暂缓，待后续确认 |

---

## 六、待办事项规范

### 必填字段

| 字段 | 要求 |
|------|------|
| 待办内容 | 可执行的具体动作，不能是模糊描述 |
| 责任人 | 具体到人，不能是部门名 |
| 截止时间 | YYYY年MM月DD日 |
| 状态 | 待开始/进行中/已完成/已延期 |

### 写法规范

| 正确 ✅ | 错误 ❌ |
|---------|---------|
| 输出V2.1版本PRD初稿 | 跟进PRD |
| 完成主界面设计稿 | 设计相关事宜 |
| 与客户确认需求优先级 | 沟通需求 |

### 信息不完整时标注

- 无明确责任人 → `[待确认责任人]`
- 无明确截止时间 → `[待确认截止时间]`
- 两者都缺失 → `[待确认责任人和截止时间]`

### 状态流转

- 上次会议待办未完成 → 本次纪要标注"已延期"并注明原因
- 已完成待办保留在纪要中，方便追踪

---

## 七、表述规范

### 语言风格

- 书面语，不用口语、语气词
- 结论用肯定句式，不用"可能""大概""好像"
- 分歧用客观描述，不偏向任何一方

### 角色标注

- 首次提到用"姓名（角色）"，后续直接用姓名
- 未参会但受影响的人标注 `[需同步]`
- 对外沟通内容标注 `[需与XX确认]`

### 敏感内容处理

- 涉及客户或第三方的敏感评价，不写入正式纪要
- 如确需记录，标注 `[内部讨论，不外传]`

---

## 八、会议类型适配规范

### 需求评审

- 侧重：功能清单、优先级、技术可行性结论
- 每个功能点标注评审结果：通过/需修改/延期/取消

### 项目复盘

- 侧重：问题分析、改进措施、责任分工
- 每个问题标注改进措施和验证时间

### 方案讨论

- 侧重：各方案对比、最终选型和理由
- 记录未选中方案及淘汰原因

### 日常站会

- 侧重：进度同步、阻塞问题、当日计划
- 每人用"昨日进展 + 今日计划 + 阻塞项"三段式记录

### 客户沟通

- 侧重：客户诉求、我方承诺、后续行动
- 承诺事项标注 **"【承诺】"** 标记

---

## 九、文件命名与分发规范

### 文件命名

- 格式："会议纪要-会议主题-YYYYMMDD"
- 示例："会议纪要-V2.1需求评审-20260713"

### 分发时机

- 会议结束后24小时内完成整理并发送

### 分发对象

- 参会人员必发
- 未参会但待办涉及的人员必发，标注 `[需关注]`
- 旁听人员选发

## 十、录音转写处理规范

### 10.1 噪音与无效信息过滤

录音转写文字中常见噪音类型及处理方式：

| 噪音类型 | 示例 | 处理方式 |
|---------|------|---------|
| 填充词 | "嗯""啊""那个""然后""就是""这个" | 直接删除 |
| 口头禅 | "说实话""我觉得吧""你懂的" | 直接删除 |
| 重复表述 | 同一段话被转写2-3次 | 保留一次，删除重复 |
| 语气词堆叠 | "嗯嗯嗯""啊啊" | 全部删除 |
| 无效过渡 | "那个什么""这个那个" | 删除或替换为书面语 |
| 寒暄闲聊 | "最近怎么样""今天天气不错" | 直接删除 |

### 10.2 转写错误识别

常见转写错误类型：

| 错误类型 | 示例 | 处理方式 |
|---------|------|---------|
| 人名错误 | "张山"（应为"张三"） | 结合上下文+项目文档纠正，无法确认则标注 `[转写存疑]` |
| 术语错误 | "消系"（应为"消息"） | 结合项目上下文纠正 |
| 数字错误 | "2025年7月"（应为"2026年7月"） | 结合常识和上下文判断，存疑则标注 |
| 否定词丢失 | "可以"（应为"不可以"） | 结合上下文语义判断，存疑则标注 |
| 同音字错误 | "登陆"（应为"登录"） | 结合上下文纠正 |

### 10.3 发言分段修复

转写文字常见问题：

| 问题 | 原因 | 处理方式 |
|------|------|---------|
| 一人发言被拆成多段 | 转写按停顿自动分段 | 合并为一段完整发言 |
| 多人发言混在一起 | 多人同时说话 | 按语义和说话风格拆分 |
| 发言人标记丢失 | 转写未识别说话人 | 根据上下文推断或标注 `[发言人不明]` |
| 议题之间无分隔 | 转写无智能分段 | 按主题切换点手动分段 |

### 10.4 内容完整性判断

以下情况表明录音可能存在内容缺失：

- 话题突然跳转，中间无任何过渡
- 结论出现但前面没有对应的讨论过程
- 某人突然提及之前未出现过的事项
- 时间线或因果关系存在明显断裂

处理方式：标注 `[内容可能缺失]`，不自行编造内容填补。

### 10.5 逻辑自洽检查清单

整理前必须检查：

- [ ] 同一人的发言是否前后一致？
- [ ] 时间线是否连贯（无已完成又说未开始）？
- [ ] 因果关系是否完整（每个"因为"都有对应的"所以"）？
- [ ] 关键决策是否有讨论过程支撑？
- [ ] 待办事项是否有明确的责任人？
- [ ] 话题切换是否自然，有无跳断？

---

## 十一、适用范围

本规范适用于所有类型的会议纪要整理：
- 需求评审会
- 项目复盘会
- 方案讨论会
- 日常站会
- 客户沟通会
- 周会/月会
- 临时讨论会

---

## 十二、配置方式

本规范配置为 Trae 的全局规则后，会议纪要整理 Agent 会自动读取并遵守。临时特殊要求在对话中说明即可，临时说明优先级高于本规范。
