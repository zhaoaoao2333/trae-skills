# 会议纪要模板

> 本文件提供会议纪要输出的标准格式和各类型会议的场景模板。
> 遵循 `references/03-规则规范/会议纪要整理规范.md` 中的规则。

---

## 一、结构确认模板

复杂会议（多议题、多角色、有分歧）在输出完整纪要前，必须先输出以下结构确认内容：

```
【会议主题】：XXX
【会议类型】：需求评审/项目复盘/方案讨论/日常站会/客户沟通

【基本信息】：
- 会议时间：YYYY年MM月DD日 HH:MM-HH:MM
- 会议地点：XXX
- 参会人员：XXX（角色）、XXX（角色）
- 主持人：XXX
- 记录人：XXX

【核心议题预览】：
- 议题1：XXX（预计核心决策点）
- 议题2：XXX
- 议题3：XXX

以上议题是否完整？确认后我将输出完整纪要。有调整请告诉我。
```

简单会议（单一议题、参会人少）跳过此步骤，直接输出完整纪要。

## 三、场景模板

### 3.1 需求评审会

```markdown
# 【产品名称】【版本】需求评审会议纪要

## 基本信息
- **会议时间**：YYYY年MM月DD日 HH:MM-HH:MM
- **参会人员**：产品（XXX）、开发（XXX）、设计（XXX）、测试（XXX）
- **主持人**：XXX
- **记录人**：XXX

## 会议目的
评审【版本】需求清单，确认功能优先级，评估技术可行性。

## 核心结论
1. 确定本版本包含X个功能模块
2. XX功能延期到下个版本
3. 设计稿需在MM月DD日前完成

## 需求评审结果
| 功能模块 | 评审结果 | 说明 |
|---------|---------|------|
| 功能A | 通过 | 无异议 |
| 功能B | 需修改 | 需补充XX场景的处理逻辑 |
| 功能C | 延期 | 开发量较大，延至下版本 |

## 议题一：功能优先级讨论
**讨论内容**：
- XXX（产品）提出本版本计划包含X个功能模块
- XXX（开发）评估XX功能开发量较大，建议延期
- XXX（产品）建议将XX功能优先级提升

**结论：** 确定本版本包含X个功能模块，XX功能延至下个版本。

## 议题二：技术可行性确认
**讨论内容**：
- XXX（开发）表示核心功能开发需要X个工作日
- XXX（开发）指出XX功能依赖第三方接口，需确认接口就绪时间

**结论：** 开发周期定为X个工作日，XX接口确认后再评估。

## 待办事项
| 序号 | 待办内容 | 责任人 | 截止时间 | 状态 |
|------|---------|--------|---------|------|
| 1 | 输出最终PRD | XXX（产品） | MM月DD日 | 待开始 |
| 2 | 完成设计稿 | XXX（设计） | MM月DD日 | 待开始 |
| 3 | 搭建开发环境 | XXX（开发） | MM月DD日 | 待开始 |
```

## 四、质量自检清单

输出纪要后逐项检查：

### 基础检查项
- [ ] 基本信息是否完整（时间、地点、参会人、记录人）？
- [ ] 核心结论是否都是"决定了什么"而非"讨论了什么"？
- [ ] 每个议题是否有明确结论（或标注了 `[待决策]`）？
- [ ] 每个待办是否有责任人和截止时间（或标注了 `[待确认]`）？
- [ ] 同一议题的内容是否合并（非流水账）？
- [ ] 口语化表述是否已转为书面语？
- [ ] 分歧点是否如实记录（不强行统一）？
- [ ] 未参会但受影响的人是否标注了 `[需同步]`？
- [ ] 敏感内容是否标注了 `[内部讨论，不外传]`？
- [ ] 文件命名是否符合"会议纪要-主题-YYYYMMDD"格式？

### 录音转写专项检查项
- [ ] 填充词和口头禅是否已过滤？
- [ ] 重复表述是否已去重？
- [ ] 转写可疑的人名/术语/数字是否已标注 `[转写存疑]`？
- [ ] 内容明显缺失处是否已标注 `[内容可能缺失]`？
- [ ] 逻辑不自洽处是否已向 PM 确认后再写入纪要？
- [ ] 发言分段是否正确（一人发言未拆散、多人未混排）？
