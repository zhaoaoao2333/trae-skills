# 会议纪要整理技能

> 将会议原始记录整理成结构清晰、重点突出、结论明确的标准化会议纪要。
> 支持通义听悟/飞书妙记等工具的转写文字、手写笔记、零散要点等多种输入形式。

---

## 核心原则

1. **PM 驱动**：结构确认和纪要输出需 PM 确认，AI 不替 PM 做决策。
2. **提炼而非复述**：不逐字记录，提炼核心观点、决策和行动项。
3. **决策导向**：每个议题必须有明确结论，未形成结论的标注 `[待决策]`。
4. **行动明确**：每个待办必须有责任人、截止时间和可执行的具体动作。
5. **结构清晰**：按议题组织，不按时间流水账，同议题内容合并。
6. **如实记录分歧**：保留关键分歧点，不强行统一为"一致通过"。
7. **经验沉淀**：每次整理后归纳问题与经验，判断是否需要更新规则。

---

## 意图确认机制

> **适用范围**：主调度器AI、会议纪要整理Agent。

### 无效信号清单（一律视为未确认）

| 信号类型 | 示例 | AI正确处理 |
|---------|------|-----------|
| 模糊回应 | "好的""嗯""行""知道了" | 视为未确认，追问："请确认纪要内容是否准确..." |
| 转移话题 | 不回答当前问题，说别的事 | 视为未确认，拉回当前问题 |
| 提出新问题 | "那XX怎么办" | 视为未确认，先处理原问题 |
| 沉默/无回复 | | 等待回复，不自动推进 |
| 部分回应 | 只回答了多问题中的一个 | 视为未确认，追问其余问题 |
| 情绪性回应 | "随便""都行""你看着办" | 视为未确认，给出方案请PM选择 |
| 反问/质疑 | "为什么要这样写" | 视为未确认，先解释再重新请求确认 |

### 有效确认信号（必须同时满足）

1. PM明确使用了确认词汇：**确认、可以、没问题、继续、就这样**
2. PM的回复**直接回应了AI当前提出的问题/方案**
3. PM的回复**没有歧义**，只有一种合理解读

### 行动前意图检查三问

**第一问：我理解了什么？** — 复述对PM意图的理解
**第二问：PM确认了吗？** — 检查回复是否属于有效确认信号
**第三问：我的理解有歧义吗？** — 如有歧义给出方案供选择

## 阶段一：输入接收与评估

### 步骤 1.1 — 接收输入

接受以下任意形式的输入：
- 通义听悟等工具生成的会议转写文字
- 飞书妙记、钉钉闪记等工具导出的逐字稿
- 用户手写的会议笔记
- 零散的会议要点

### 步骤 1.2 — 录音转写预处理（如输入为转写文字）

如果输入来自录音转写工具（通义听悟/飞书妙记等），必须先执行预处理：

**噪音与无效信息过滤**：
- 去除填充词（"嗯""啊""那个""然后""就是""这个"）
- 去除语气词和口头禅
- 去除重复表述（转写常把一句话重复记录多次）
- 去除寒暄、闲聊、与议题无关的内容

**转写错误识别**：
- 识别可能的人名/术语识别错误（如"张三"转写为"张山"）
- 识别数字/日期转写错误
- 标注可疑内容为 `[转写存疑]`

**发言分段修复**：
- 修复多人同时说话导致的段落混乱
- 按发言人和议题重新分段
- 合并因转写分段错误而拆散的连续发言

### 步骤 1.3 — 评估输入完整度

| 评估项 | 判断标准 | 处理方式 |
|--------|---------|---------|
| 内容足够 | 能提取会议时间、参会人、讨论主题 | 进入逻辑自洽检查 |
| 内容不足 | 只有几个关键词或片段 | 主动追问缺失信息 |
| 信息模糊 | 有内容但时间/人员/议题不明确 | 先确认基本信息 |

**主动追问机制**：

以下情况必须追问，不得自行假设（**不限制问题数量**，列出所有问题逐一确认）：
- 会议时间不明确
- 参会人员或角色不清楚
- 会议目的无法从内容中推断
- 多个议题边界模糊

### 步骤 1.4 — 逻辑自洽检查

预处理完成后，先自己梳理内容逻辑，检查以下问题：

| 问题类型 | 示例 | 处理方式 |
|---------|------|---------|
| 前后矛盾 | 同一人先说A方案被采纳，后又说B方案被采纳 | 必须反问确认 |
| 时间线冲突 | 先说本周完成，后又说计划下周开始 | 必须反问确认 |
| 因果缺失 | "因为接口有问题，所以延期"，但前面没提到接口有问题 | 必须反问确认 |
| 结论凭空出现 | 议题讨论中没有决策过程，直接出现结论 | 必须反问确认 |
| 话题跳断 | 话题突然从一个议题跳到另一个，中间无过渡 | 标注 `[内容可能缺失]` |
| 待办无责任人 | 有人提出"要做什么"但没人说"我来做" | 追问确认责任人 |

**关键原则**：逻辑不自洽时**先理清再整理**，不得强行编造逻辑后输出纪要。列出所有问题一次性反问，不限制问题数量。

### 步骤 1.5 — 评估内容复杂度

| 复杂度 | 判断标准 | 处理方式 |
|--------|---------|---------|
| 简单 | 单一议题、参会人少、逻辑自洽 | 直接输出完整纪要，不额外确认结构 |
| 复杂 | 多议题、多角色、有分歧、逻辑有疑点 | 先澄清问题，再输出议题框架确认 |

## 阶段二：基本信息提取与结构确认

### 步骤 2.1 — 提取基本信息

从原始记录中提取或追问以下信息：

**必填字段**：
- 会议时间（格式：YYYY年MM月DD日 HH:MM-HH:MM）
- 会议地点（线下写具体位置，线上写平台名称）
- 参会人员（姓名 + 角色/部门，首次出现标注）
- 记录人

**选填字段**：
- 主持人
- 请假人员
- 旁听人员
- 会议目的（一句话说明）

### 步骤 2.2 — 议题识别与归类

- 扫描全部内容，识别讨论的主题切换点
- 同类讨论合并为一个议题（不按时间流水账）
- 去除寒暄、闲聊、跑题内容
- 每个议题提炼名称，格式："议题X：主题"

### 步骤 2.3 — 结构确认（复杂会议强制）

复杂会议必须先输出议题框架，等 PM 确认：

确认格式遵循 `references/02-模板文件/会议纪要模板.md` 中的"结构确认模板"。

简单会议跳过此步骤，直接进入阶段三。

---

## 阶段三：内容整理与纪要生成

### 步骤 3.1 — 核心结论提炼

- 从每个议题中提取"决定了什么"（不是"讨论了什么"）
- 当场形成决策的直接写入结论
- 未形成决策的标注 `[待决策]` 并注明原因
- 3-5 条，按重要性排序，每条控制在 30 字以内

### 步骤 3.2 — 议题讨论整理

按议题逐个整理：
- 提炼各发言人核心观点，标注发言人身份
- 口语转书面简洁表述
- 多个方案时保留各自优缺点简述
- 结论用 **"结论："** 加粗标注
- 分歧点如实记录，不强行统一

### 步骤 3.3 — 待办事项提取

每个待办必须明确：
- **内容**：可执行的具体动作（不能是"跟进XX"这种模糊描述）
- **责任人**：具体到人（不能是"产品部"这种部门名）
- **截止时间**：具体日期
- **状态**：待开始/进行中/已完成/已延期

信息不完整时标注：
- 无明确责任人 → `[待确认责任人]`
- 无明确截止时间 → `[待确认截止时间]`

### 步骤 3.4 — 结构化输出

按照 `references/03-规则规范/会议纪要整理规范.md` 的结构和 `references/02-模板文件/会议纪要模板.md` 的格式输出最终纪要。

### 步骤 3.5 — 质量自检

自检清单：
- [ ] 基本信息是否完整（时间、地点、参会人、记录人）？
- [ ] 核心结论是否都是"决定了什么"而非"讨论了什么"？
- [ ] 每个议题是否有明确结论（或标注了 `[待决策]`）？
- [ ] 每个待办是否有责任人和截止时间（或标注了 `[待确认]`）？
- [ ] 同一议题的内容是否合并（非流水账）？
- [ ] 口语化表述是否已转为书面语？
- [ ] 分歧点是否如实记录？
- [ ] 未参会但受影响的人是否标注了 `[需同步]`？
- [ ] **录音转写内容**：转写存疑点是否已标注 `[转写存疑]`？
- [ ] **录音转写内容**：内容可能缺失处是否已标注 `[内容可能缺失]`？
- [ ] **录音转写内容**：逻辑不自洽处是否已向 PM 确认后再写入纪要？

---

## 阶段四：交付与经验沉淀

### 步骤 4.1 — 交付纪要

向 PM 交付标准化会议纪要（Markdown 格式）。

### 步骤 4.2 — 输出后追问

主动询问：
> "以上纪要是否准确？待办事项的责任人和截止时间是否需要补充？"

### 步骤 4.3 — 整理归纳问题

输出完成后，整理本次整理过程中的问题和经验：

**问题归纳**：
- PM 反馈了哪些修改意见？归纳为哪几类？
- 哪些问题是原始记录信息不完整导致的？
- 哪些问题是 Agent 理解或归类有误导致的？

**经验总结**：
- 某类会议的最佳整理方式
- 需要补充到 `会议纪要整理规范.md` 中的新规则

> 这些经验在后续整理中持续优化，积累到一定量后判断是否更新规范。
